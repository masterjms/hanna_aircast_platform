# MQTT 방송 제어 — 실행 스크립트 사용법

## 실행 순서 (요약)

**테스트할 때는 이 순서대로 bat 파일만 실행하면 됩니다.**

1. `전체_시작.bat` 더블클릭 → Icecast+마이크, MQTT 브로커, 결과 모니터 창까지 한 번에 시작
   - (안 될 경우 아래 "개별 실행" 순서로 하나씩 실행)
2. `control.bat` 더블클릭 → 메뉴에서 `1) 방송 시작` 선택 → ESP32 반응 확인
3. 끝나면 `전체_종료.bat` 더블클릭 → 전부 정리

### 개별 실행 (전체_시작.bat이 안 될 때)

1. `D:\xWIFI_Icecast\작업지시서\실행스크립트\Icecast_시작.bat`
2. `mqtt_broker_start.bat`
3. `monitor.bat`
4. `control.bat`

> ⚠️ **`전체_시작.bat`/`전체_종료.bat`은 이 세션 자동화 테스트 환경에서 간헐적으로 실행이 깨지는 현상이 있었습니다** (한글 경로+배치파일 파싱 관련, 원인을 완전히 특정하지 못함). 실제 탐색기에서 더블클릭했을 때는 정상 동작할 가능성이 높지만, **처음 사용하실 때 한 번은 직접 확인해 주세요.** 안 되면 위 "개별 실행" 순서대로 하나씩 실행하시면 됩니다 — 개별 스크립트들은 전부 정상 동작이 확인되었습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `mosquitto.conf` | MQTT 브로커 설정 파일 (포트 1883, 익명 허용 — 1차 데모용) |
| `mqtt_broker_start.bat` | MQTT 브로커 실행 (서비스 중지 후 우리 설정으로 수동 실행) |
| `mqtt_broker_stop.bat` | MQTT 브로커 종료 |
| `control.bat` | **번호 메뉴로 방송 시작/종료/상태 체크** |
| `monitor.bat` | 단말의 result/status를 실시간으로 보여주는 상시 감시 창 |
| `전체_시작.bat` | Icecast+마이크 → MQTT 브로커 → 모니터 순서로 한 번에 시작 |
| `전체_종료.bat` | MQTT 브로커 → 모니터 → Icecast+마이크 순서로 한 번에 종료 |
| `session.txt` | 방송 세션 번호 자동 저장/증가 (건드릴 필요 없음) |
| `file_server_start.bat` | 파일 다운로드 테스트용 로컬 HTTP 서버 시작 (포트 9002) |
| `file_server_stop.bat` | 파일 다운로드 테스트용 서버 종료 |
| `files\` | 파일 서버가 서빙하는 폴더 — FILE_START로 테스트할 파일을 여기에 넣기 |
| `file_counter.txt` | FILE_START의 `job_id` 자동 저장/증가 (건드릴 필요 없음) |
| `config_counter.txt` | CONFIG의 `config_version` 자동 저장/증가 (건드릴 필요 없음) |
| `ota_counter.txt` | OTA_START의 `job_id` 자동 저장/증가 (건드릴 필요 없음) |
| `files\update\` | OTA용 `IOT_RADIO.pkg`를 넣는 폴더 (파일 서버가 `9002/update/...`로 서빙) |

## 사전 준비 개념

**MQTT는 오디오를 직접 다루지 않습니다.** `control.bat`은 ESP32에게 "지금부터 방송 시작해라"는 신호(LIVE_START)만 보낼 뿐, 실제 마이크 오디오는 Icecast 쪽에서 별도로 계속 흐르고 있어야 합니다. 그래서 **Icecast+마이크 소스가 항상 MQTT보다 먼저 켜져 있어야** 합니다 (위 실행 순서가 이걸 보장합니다).

## `control.bat` 메뉴

```
1) 방송 시작 (LIVE_START 전송)
2) 방송 종료 (LIVE_STOP 전송)
3) 상태 체크 (5초간 STATUS/result 수신 대기)
4) 결과 모니터 창 열기
5) 파일 방송 시작 (FILE_START 전송)
6) 파일 방송 취소 (FILE_STOP 전송)
7) CONFIG 전송 (status/live_stats 주기 설정)
8) OTA 업데이트 시작 (OTA_START 전송)
0) 종료
```

- **1) 방송 시작**: 세션 번호를 자동 증가시키고 `iotradio/village/00000001/cmd` 토픽으로 LIVE_START(JSON, `frame_ms:40` 포함)를 발행합니다. **오디오 자체는 안 켭니다** — Icecast+마이크가 이미 켜져 있어야 합니다.
- **2) 방송 종료**: 마지막 세션 번호로 LIVE_STOP을 발행합니다. 이것도 FFmpeg/Icecast는 건드리지 않습니다 — 오디오 소스를 끄고 싶으면 `Icecast_종료.bat` 또는 `전체_종료.bat`을 실행하세요.
- **3) 상태 체크**: 단말이 보내는 status/result를 아무 키나 누를 때까지 계속 구독해서 화면에 보여줍니다(시간 제한 없음). `4) 결과 모니터 창`이 열려 있어도 그건 건드리지 않고, 이번에 새로 띄운 구독만 종료합니다.
- **4) 결과 모니터 창 열기**: `monitor.bat`을 새 창으로 엽니다.
- **5) 파일 방송 시작**: `files\` 폴더 안의 파일 목록을 보여주고, 파일명을 입력받아 size/sha256을 자동 계산한 뒤 FILE_START(JSON)를 발행합니다. `https_url`은 `http://192.168.0.5:9002/<파일명>`으로 자동 생성됩니다. **`file_server_start.bat`이 이미 켜져 있어야 합니다.**
- **6) 파일 방송 취소**: FILE_STOP을 발행합니다.
- **7) CONFIG 전송**: `status_interval_sec`/`live_stats_interval_sec`/`event_qos` 값을 물어보고(Enter는 기본값 30/10/0) `iotradio/all/config` 토픽으로 **retain 옵션과 함께** 발행합니다. 전체 단말 공통 설정이라 `TARGET`(개별/마을/전체) 선택과는 무관하게 항상 전체 단말에 적용됩니다. `config_version`은 `config_counter.txt`로 자동 증가하며, `village_id`도 테스트용 고정값(`00000001`)으로 같이 발행합니다. **ESP32측 적용까지 실측 확인된 상태입니다.**
- **8) OTA 업데이트 시작**: `files\update\IOT_RADIO.pkg`가 있어야 합니다. size/sha256을 자동 계산하고 `OTA_START`를 발행합니다(retain 없음). pkg 안에 어떤 칩(P4/C6)용 펌웨어가 들었는지는 P4가 자체적으로 판단하므로 서버가 따로 지정하지 않습니다. `job_id`는 `ota_counter.txt`로 자동 증가합니다. 발행 후 `3) 상태 체크`로 `OTA_STATUS`(ACCEPTED/PREPARE/DOWNLOADING/VERIFYING)를 지켜보세요. **2026-08-20부터 별도 승인 절차가 없습니다** — 검증까지 통과하면(COMPLETED) 단말이 자동으로 MQTT/HTTP/Icecast 연결을 모두 끊고 실제 업데이트를 적용하므로, 그 시점부터는 상태 보고가 안 옵니다 — 재부팅 후 재접속되는 `STATUS`의 펌웨어 버전으로 최종 성공 여부를 확인하세요.

## 파일 다운로드(FILE_START) 테스트

**주의: 이건 검증/데모용 로컬 서버입니다.** 실제 운영 중인 AWS(`iot_radio.co.kr`) 파일 서버와는 완전히 별개이며, 그쪽은 건드리지 않습니다.

1. `files\` 폴더에 테스트할 파일을 넣습니다 (샘플로 `test-sample.txt` 하나 들어있음).
2. `file_server_start.bat` 더블클릭 → 포트 9002에서 서빙 시작.
3. `control.bat` → `5) 파일 방송 시작` → 파일명 입력 → 자동으로 size/sha256 계산 후 FILE_START 발행.
4. 결과는 `monitor.bat` 창에서 `FILE_END`(성공/실패) 또는 `FILE_ABORT`(BUSY 등)로 확인.
5. 끝나면 `file_server_stop.bat`으로 종료.

`job_id`는 `file_counter.txt`에 자동 저장/증가됩니다 (건드릴 필요 없음).

## OTA 업데이트 테스트

**주의: 1차는 평문 HTTP + 서명 없는 sha256 검증만 사용하는 내부망 전용 테스트입니다.** 실서비스 배포 전에는 pkg 서명이 필수입니다(단말측 사양서 참고).

1. `files\update\` 폴더에 `IOT_RADIO.pkg`를 넣습니다.
2. `file_server_start.bat`이 켜져 있어야 합니다(FILE_START와 동일한 서버).
3. `control.bat` → `8) OTA 업데이트 시작` → 대상 선택 → `OTA_START` 발행.
4. `3) 상태 체크`로 `OTA_STATUS`를 지켜봅니다(`ACCEPTED`/`PREPARE`/`DOWNLOADING`/`VERIFYING`). 2026-08-20부터 `OTA_APPLY` 승인 단계가 없어져서, 검증까지 통과하면 단말이 별도 승인 없이 자동으로 적용을 시작하고 네트워크를 끊습니다(정상).
5. 단말 재부팅 후 재접속되면 `STATUS`의 펌웨어 버전을 확인해 성공 여부를 판단합니다.

`job_id`는 `ota_counter.txt`에 자동 저장/증가됩니다 (건드릴 필요 없음).

## 설정값 바꾸기

`control.bat` 상단의 다음 값을 메모장으로 열어 수정:

```bat
set "VILLAGE=00000001"
set "TARGET=iotradio/village/%VILLAGE%/cmd"
```

- 특정 단말 1대만 제어: `set "TARGET=iotradio/device/<mac_nocolon>/cmd"`
- 전체 단말: `set "TARGET=iotradio/all/cmd"`

## 문제가 생겼을 때

- **LIVE_START는 보냈는데 소리가 안 남** → Icecast/마이크 소스가 안 켜져 있는 경우가 가장 흔함. `http://localhost:8000/live` 접속해서 스트림 살아있는지 먼저 확인.
- **단말이 브로커에 접속 못 함** → 방화벽 1883 규칙 확인, 단말이 `localhost`가 아니라 `PC_LAN_IP:1883`(예: `192.168.0.5:1883`)로 접속하는지 확인, 같은 LAN인지 확인.
- **publish는 되는데 단말 반응 없음** → 단말이 구독 중인 topic과 `TARGET` 값이 일치하는지 확인 (MAC은 콜론 없는 소문자).
- **1883이 이미 점유됨** → 자동 등록된 mosquitto 서비스가 떠 있는 것. `mqtt_broker_stop.bat` 실행 후 `mqtt_broker_start.bat` 재실행.
- **`전체_시작.bat`/`전체_종료.bat`이 이상하게 동작함** → 위 "개별 실행" 순서대로 하나씩 실행.
