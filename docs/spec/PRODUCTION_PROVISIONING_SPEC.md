## 1. 왜 만드나

### 1.1 MAC 오타가 조용히 실패한다

MQTT 토픽 구조 전체가 C6의 STA MAC을 키로 쓴다.

```text
iotradio/device/58e6c5f2cc74/config
```

손으로 옮겨 적다 한 글자 틀리면 **단말이 마을 배정을 영영 받지 못한다.** 에러도 나지 않고 그냥 오지 않는다. 현장에서 원인을 찾기 가장 어려운 종류다.

### 1.2 버튼 4개로 설정을 치는 것은 느리고 틀리기 쉽다

현재 설정 화면은 문자 하나를 KEY3/KEY4로 골라 KEY2로 넣는다. 비밀번호가 길면 오래 걸리고, 틀려도 화면에서 알아채기 어렵다.

## 2. 진입 조건

기존 부팅 콤보와 같은 방식으로 하나 추가한다. 정확히 두 키만 눌린 경우에만 인정하고, 유지 시간 동안 계속 확인한다.

| 콤보 | 모드 |
|---|---|
| KEY1 + KEY2 | USB 업데이트 (기존) |
| KEY3 + KEY4 | 생산자 설정 (기존) |
| **KEY1 + KEY4** | **생산/현장 모드 (신규)** |

`APP_BOOT_KEY_MODE_PHONE_PROV`를 `app_boot_key_mode_t`에 추가한다.

### 2.1 이 모드에서 도는 것

생산자 설정 모드와 같은 골격이다. 자기 화면만 그리고 `app_startup_task`는 돌리지 않는다.

| | 도는가 |
|---|---|
| 화면(LVGL) | 예 — 전용 화면 하나 |
| **SDIO RPC** | **예 — C6 MAC이 여기서 온다** |
| Wi-Fi / MQTT | 아니오 |
| RF | 아니오 |
| app_control / 오디오 | 아니오 |

**SDIO를 올려야 하는 것이 생산자 설정 모드와 다른 점이다.** 화면에 띄울 C6 MAC과 모델·버전이 SDIO로 오기 때문에, 이 모드는 Wi-Fi를 건너뛰면서도 그 경로만 따로 세운다. 어떻게 세우는지는 §7.1에 있다.

### 2.2 MAC을 못 받았을 때

`HELLO`가 오기 전에는 **바코드와 QR을 그리지 않는다.** MAC이 0으로 채워진 코드가 찍혀 나가는 것이 안 나오는 것보다 나쁘다.

화면에 "C6 응답 대기 중"을 표시하고, 일정 시간이 지나도 안 오면 그 사실을 표시한다.

**대신 쓸 값을 두지 않는다 (2026-08-27 결정).** C6에서 값을 못 읽으면 코드를 출력하지 않는 것이 맞다. 이 상태는 생산에서 수리로 처리한다.

초안에 있던 "정상 부팅 때 받은 MAC을 P4 NVS에 캐시해 두었다가 대신 쓴다"는 예비책은 **채택하지 않는다.** C6만 교체한 단말에서 옛 MAC이 찍혀 나갈 수 있고, 그러면 §1.1이 막으려던 조용한 실패가 그대로 재현된다 — 스캐너는 화면의 "캐시값" 경고를 읽지 않는다. **코드가 안 나오는 것은 고장을 알리는 신호이지 가려야 할 불편이 아니다.**

현재 동작:

| 시점 | 화면 |
|---|---|
| `HELLO` 전 | MAC/C6 버전 자리에 `waiting...`, 바코드·QR 없음 |
| `15초` 무응답 | `NO RESPONSE FROM C6 - check the board` |
| `HELLO` 수신 | 바코드·QR을 그리고 `READY - scan a code` |
| `10분` 방치 | 일반 부팅으로 재시작 |

### 2.3 무입력 타임아웃

`10분`(`PROV_UI_IDLE_REBOOT_MS`) 동안 아무 일도 없으면 일반 부팅으로 재시작한다. 콤보를 잘못 눌러 들어왔는데 그대로 두고 가면 그 단말은 방송을 받지 못한 채 남는다. 시리얼로 무언가 들어오면 이 시계는 0으로 되돌아간다.

## 3. 화면

**바코드와 QR을 왼쪽/오른쪽에 나란히 둔다.** 둘 다 항상 띄우고, 어느 것을 찍을지는 작업자가 고른다.

글자 정보는 **출처로 나눠 배치한다.** 왼쪽은 P4가 아는 값, 오른쪽은 C6에서 온 값이다. 어느 쪽 펌웨어를 봐야 하는지가 배치로 드러난다.

```text
+------------------------------------------------------------+
|                  PRODUCTION / FIELD MODE                   |
|                                                            |
|         [ P4 ]                      [ C6 ]                 |
|   MODEL  IOT-1000             MAC   58:E6:C5:F2:CC:74      |
|   P4     V.260823-1           C6    V.260823-1             |
|                                                            |
|   +---------------------+      +---------------------+     |
|   |  ||| || |||| | |||  |      |        [QR]         |     |
|   +---------------------+      +---------------------+     |
|   58e6c5f2cc74                 58e6c5f2cc74|               |
|                                IOT-1000|V.260823-1|        |
|                                IOT-1000C6|V.260823-1       |
|                                                            |
|   <<XWIFI-PROV v1 READY>>            SERIAL: ready         |
+------------------------------------------------------------+
```

각 코드 아래에 **담긴 내용을 글자로 적는다.** 스캔이 안 될 때 사람이 옮겨 적을 수 있고, 찍은 값이 맞는지도 눈으로 확인된다.

LVGL 9.1에 둘 다 내장돼 있다. Kconfig만 켜면 된다.

```text
CONFIG_LV_USE_BARCODE   (Code 128)
CONFIG_LV_USE_QRCODE
```

### 3.1 1D 바코드 — MAC만

내용은 **콜론 없는 소문자 hex 12자**다.

```text
58e6c5f2cc74
```

Code 128을 쓴다. 짧게 나오고 어느 스캐너든 읽는다.

서버 등록 화면의 MAC 칸 하나만 채울 때 쓴다.

### 3.2 QR — 전 항목

QR에는 항목을 구분자로 이어 담는다.

```text
58e6c5f2cc74|IOT-1000|V.260823-1|IOT-1000C6|V.260823-1
```

| 순서 | 항목 | 출처 |
|---|---|---|
| 1 | C6 STA MAC (콜론 없음, 소문자) | `sdio_rpc_get_c6_sta_mac()` |
| 2 | P4 모델 코드 | `MODEL_PROJECT_CODE` |
| 3 | P4 펌웨어 버전 | `MODEL_SYSTEM_VERSION` |
| 4 | C6 모델 코드 | `sdio_rpc_get_c6_model_code()` |
| 5 | C6 펌웨어 버전 | `sdio_rpc_get_c6_system_version()` |

1번은 **MQTT `client_id`와 같은 값**이다. 서버가 브로커 로그와 대조할 때 그대로 쓴다.

구분자는 **`|`** 를 쓴다. MAC(hex), 모델 코드(영문), 버전(`V.` + 숫자 + `-` + 숫자) 어디에도 나오지 않는 문자다. 값 안에 구분자가 섞일 일이 없으므로 서버가 단순히 쪼개면 된다.

### 3.2.1 이 문자열을 등록 화면에 넣는 두 가지 방법

**HID 스캐너는 키보드처럼 내용을 타이핑한다.** 그 뒤가 두 갈래다.

| | A. 스캐너가 Tab으로 나눔 | **B. 서버가 문자열을 쪼갬** |
|---|---|---|
| 등록 화면 | 항목마다 입력칸 | **입력칸 하나** |
| 스캐너 설정 | **구분자→Tab 치환 규칙 필요** | 기본 설정 그대로 |
| 서버 코드 | 불필요 | **분리 코드 필요 (한 줄짜리)** |
| 스캐너를 바꾸면 | 새 스캐너에 규칙 다시 등록 | 그대로 됨 |

**B를 권한다.** 스캐너 기종·펌웨어마다 다른 설정에 의존하지 않고, 현장에서 스캐너를 바꿔도 그대로 동작한다. 서버가 추가할 코드는 구분자로 나누는 것뿐이다.

A는 서버를 못 고칠 때의 방법이다. 둘은 배타적이지 않아서 **등록 화면이 두 방식을 다 받아도 된다.**

### 3.2.2 B로 갈 때 서버가 정할 것

**끝 표시가 있어야 서버가 "다 들어왔다"를 안다.** 스캐너는 접미사(suffix)를 붙여 보내며, 기본값이 보통 Enter(CR)다.

```text
58e6c5f2cc74|IOT-1000|V.260823-1|IOT-1000C6|V.260823-1⏎
```

| 항목 | 권장 |
|---|---|
| 접미사 | **Enter** — 대부분 스캐너의 기본값이라 설정을 안 건드려도 된다 |
| 입력칸 | 이 문자열 전체를 받는 칸 하나 |
| 처리 시점 | Enter가 들어오면 쪼개서 각 항목에 배치 |

서버가 확인할 것:

- 항목 수가 **5개**인가. 모자라면 스캔이 잘렸거나 구형 펌웨어다.
- MAC이 **hex 12자**인가.
- 사람이 손으로 붙여넣는 경우도 같은 칸에서 받아준다. 스캐너가 없을 때 화면의 글자를 보고 칠 수 있어야 한다.

**스캔은 등록의 첫 단계일 뿐이다.** 이 문자열로 채워지는 것은 MAC과 모델·버전이고, 그 뒤의 주소 검색·마을 배정·이름 입력은 `SERVER_DEVICE_REGISTRY_2026-08-27.md` §3에 있다. 등록 화면 전체 흐름은 그쪽 §3.5다.

**항목이 늘어날 수 있다.** 나중에 생산 일련번호 등이 붙으면 6개, 7개가 된다. **"5개가 아니면 거부"보다 "앞 5개는 이 뜻이고 뒤는 무시"** 로 만들어 두면 펌웨어를 먼저 올려도 서버가 깨지지 않는다. 실제로 C6 모델이 나중에 추가되면서 4개에서 5개가 됐다.

### 3.2.3 A로 갈 때 스캐너에서 찾을 기능

읽은 데이터를 가공해 키 입력으로 내보내는 규칙이다. 제조사마다 이름이 다르다.

| 제조사 | 기능 이름 | 참고 모델(보급형 유선 2D) |
|---|---|---|
| Zebra | Advanced Data Formatting (ADF) | DS2208 계열 |
| Honeywell | Data Formatter / EZConfig | Voyager 1470g, Xenon 1950g 계열 |
| Datalogic | Advanced Formatting | QuickScan QD2430 계열 |

**구매 전 판매처에 "구분자를 Tab 키로 치환해서 보낼 수 있는지" 확인하고 실물로 시험한다.** 위 모델들은 오래된 계열이라 대체로 되지만 재고 모델과 펌웨어에 따라 다르다.

이 경우 접미사 Enter가 **마지막 칸 뒤에 와야 한다.** 중간에 오면 폼이 먼저 제출된다.

### 3.2.4 2D 스캐너를 못 구했을 때

**예비책이다.** 화면 구성은 그대로 두고 등록 화면 채우는 방법만 달라진다.

| 방법 | 내용 |
|---|---|
| 왼쪽 바코드만 사용 | MAC 한 칸만 채우고 나머지는 손으로 |
| 항목별 1D 여러 개 | 화면에 바코드를 여러 개 띄우고 순서대로 스캔 |

**전자로도 충분하다.** 없애려는 오류는 MAC 오타이고, 모델과 버전은 틀려도 조용히 실패하지 않는다.

### 3.3 사람이 읽을 값도 같이

코드만 있으면 스캐너가 없을 때 아무것도 못 한다. **MAC과 모델, 버전을 글자로도 표시한다.** 콜론이 있는 형태(`58:E6:C5:F2:CC:74`)가 사람이 옮겨 적기 쉽다.

## 4. 안드로이드 앱 연결

### 4.1 물리 경로

외부로 나오는 포트는 디버그와 OTG 둘뿐이고, **OTG는 USB 업데이트에서 P4가 호스트로 쓰고 있다.** 따라서 디버그 포트(UART0)를 쓴다.

```text
안드로이드 폰 ── USB-to-serial 보드 ── P4 디버그 헤더 (TX/RX/GND)
```

디버그 헤더에는 **DTR/RTS가 나오지 않는다.** 자동 리셋 회로가 없으므로 포트를 열 때 단말이 리셋되거나 다운로드 모드로 빠지는 문제는 없다.

보드레이트는 콘솔과 같은 **115200**이다.

### 4.2 로그와 같은 선을 쓴다

UART0은 콘솔이다. TX로 로그가 계속 나가고, RX는 지금 아무도 읽지 않는다.

- **RX**: `uart_driver_install(UART_NUM_0, ...)`로 드라이버를 올려 읽는다. RF가 쓰는 UART2와 충돌하지 않는다.
- **TX**: 이 모드에 들어가면 `esp_log_level_set("*", ESP_LOG_NONE)`으로 로그를 끈다.

### 4.3 동기점

**2차 부트로더 로그는 앱 코드가 돌기 전에 나가므로 막을 수 없다.** 앱은 어차피 로그 뭉치를 한 번 보게 된다.

로그를 끄기 직전에 배너를 한 줄 찍는다.

```text
<<XWIFI-PROV v1 READY>>
```

앱은 이 줄이 나올 때까지 버리고 그 뒤부터를 프로토콜로 읽는다. **앞에 무엇이 왔든 상관없어진다.** 배너의 `v1`로 앱이 펌웨어 세대를 판단한다.

### 4.4 프로토콜 — 지금 쓰는 설정 파일 형식을 그대로 보낸다

새 형식을 만들지 않는다. `user_setting.ini`가 이미 쓰고 있는 형식을 시리얼로 그대로 보낸다.

```text
@ZONE=1
@CHN=1
@SSID=village_ap
@PASSWORD=secret123
@SERVER=hanna-aircast.co.kr
@END
```

`user_setting.c`의 파서가 이미 이렇게 동작한다:

- 줄 단위 `@KEY=VALUE`
- 앞뒤 공백을 다듬는다
- **`@END`가 끝 표시** — 프레임 구분이 이미 있다
- **모르는 키는 경고만 남기고 넘어간다** — 앱이 새 키를 보내도 구형 펌웨어가 죽지 않는다
- `@`로 시작하지 않는 줄은 무시 — 연결 순간의 쓰레기 바이트가 걸러진다

**얻는 것**:

| | |
|---|---|
| 프레임 | `@END`로 이미 해결 |
| 쓰레기 바이트 | `@`로 시작하지 않으면 무시되므로 자연히 걸러짐 |
| 앞으로의 확장 | 모르는 키는 무시되므로 앱과 펌웨어 버전이 달라도 됨 |
| 시험 | **터미널로 손으로 쳐볼 수 있다.** 앱 없이 개발과 현장 점검이 된다 |
| 코드 | 파서를 새로 만들지 않는다 |

#### 무결성

텍스트라 눈으로 확인되고 `@END`로 끝을 알므로 CRC 없이도 대부분 걸러진다.

**CRC는 쓰지 않는다 (2026-08-27 결정).** 예전 초안에 있던 선택적 `@CRC=xxxx` 줄은 구현하지 않았고 앞으로도 넣지 않는다. 보내더라도 "모르는 키"로 무시된다.

무결성은 아래로 충분하다고 본다.

- `@END`가 와야 처리한다. 중간에 끊긴 요청은 적용되지 않는다.
- 값마다 범위를 검사한다. **하나라도 범위를 벗어나면 요청 전체를 거부한다** — 그 항목만 버리지 않는다.
- 쓴 뒤 `@GET`으로 되읽어 확인할 수 있다.
- 선이 짧고(직결 UART) 사람이 눈으로 확인하는 작업이다.

#### 값 안의 공백

파서가 값의 앞뒤 공백을 다듬는다. **다만 `@PASSWORD`와 `@MQTTPW`는 다듬지 않는다.**

공백으로 끝나는 Wi-Fi 비밀번호가 실제로 있고, 그것을 조용히 잘라내면 **붙지 않는 이유를 찾기 어렵다.** 두 키만 예외로 두고 나머지는 사람이 터미널로 칠 때 딸려오는 공백을 걷어낸다.

따옴표(`@PASSWORD="ab "`)는 쓰지 않는다 — 예외 두 곳이 파서에 처리를 더하는 것보다 싸다.

### 4.4.1 명령 전체 목록

한 요청은 `@`로 시작하는 줄 여럿에 `@END` 하나로 끝난다. **모르는 키는 무시된다.**

#### 제어

| 명령 | 뜻 |
|---|---|
| `@END` | 요청 끝. 이 줄이 와야 처리한다 |
| `@GET` | 현재 값을 읽는다 (§4.5). 다른 키와 같이 보내면 읽기만 한다 |
| `@OFF` | 저장한 것을 적용하려고 재부팅한다 (§4.7) |
| `@WIFICLR` | 저장된 Wi-Fi를 **지운다** (§4.5.1). `@SSID`/`@PASSWORD`와 같이 못 보낸다 |
| ~~`@CRC=xxxx`~~ | **사용하지 않는다.** 초안에만 있던 항목이고 구현하지 않는다 (§4.4 무결성) |

#### 설정 — 쓰기와 읽기 모두 되는 항목

| 키 | 값 | 저장 위치 |
|---|---|---|
| `@SSID` | 문자열 | Wi-Fi NVS |
| `@PASSWORD` | 문자열 | Wi-Fi NVS |
| `@SERVER` | host 또는 IP | `server_cfg` NVS |
| `@MQTTID` | 문자열 (최대 63) | `server_cfg` NVS |
| `@MQTTPW` | 문자열 (최대 127) | `server_cfg` NVS |
| `@ZONE` | 0~99 | `user_setting.ini` |
| `@CHN` | 0~255 | `user_setting.ini` |
| `@COLOR` | 0~99 | `user_setting.ini` |
| `@PIR SENSOR` | 0/1 | `user_setting.ini` |
| `@BATTERY` | 0/1 | `user_setting.ini` |
| `@REBOOT DAY` | 0~15 | `user_setting.ini` |

#### 읽기 응답에만 나오는 항목

| 키 | 뜻 |
|---|---|
| `@RESULT` | `OK` 또는 `FAIL` |
| `@ERROR` | `FAIL`일 때 이유 (§5.4) |
| `@MAC` | C6 STA MAC, 콜론 없는 소문자. **MQTT `client_id`와 같은 값** |
| `@MODEL` | P4 모델 코드 |
| `@P4` | P4 펌웨어 버전 |
| `@C6MODEL` | C6 모델 코드 |
| `@C6` | C6 펌웨어 버전 |

식별값 다섯은 쓸 수 없다. 화면의 QR과 같은 내용이라, QR을 못 찍는 상황에서 대신 쓰라고 넣었다.

#### 비밀번호 두 개는 값을 돌려주지 않는다

`@PASSWORD`와 `@MQTTPW`는 읽을 때 값을 돌려주지 않는다. **들어 있는지만** 알려준다.

```text
@MQTTPW=SET       있음
@MQTTPW=NONE      없음 (빈 값을 보냈거나 아예 안 넣었다)
```

**쓰기 응답과 `@GET`이 같은 답을 낸다.** `@PASSWORD=`를 빈 값으로 보내면 두 곳 다 `NONE`이고, 값을 보내면 두 곳 다 `SET`이다.

**값이 맞는지는 확인하지 않는다.** `SET`은 「무언가 들어갔다」까지다. 값이 맞았는지는 **그 계정으로 브로커에 붙는 것**으로 증명된다(§6.3의 2차 확인) — 브로커가 이미 비밀번호를 검증했으므로 단말에 되물을 이유가 없다.

#### `@CHN`은 예전에 `@CHANNEL`이었다

RF(+MT)가 같은 항목을 `@R,CHN=`으로 부르는데 여기만 `@CHANNEL`이라, 같은 값을 두 이름으로 부르고 있었다. **`@CHN`으로 맞췄다.**

**`@CHANNEL`도 계속 받는다.** 이미 나간 단말의 `user_setting.ini`가 그 이름으로 쓰여 있고, 못 읽으면 채널이 조용히 0이 되어 방송을 못 받는다. 저장할 때는 `@CHN`으로만 쓴다.

#### RF 명령과는 이름 공간이 다르다

송신기에서 오는 RF(+MT) 명령도 `@`로 시작하지만 **`@R,` 접두사가 붙고 형식이 다르다** (`@R,ZONE=1`, `@R,CHN=1`, `@R,VOL=5`, `@R,RESET`).

두 경로는 섞이지 않는다:

- **저장소가 다르다.** `@SSID`/`@PASSWORD`/`@SERVER`/`@MQTTID`/`@MQTTPW`는 NVS로 가고, RF가 건드리는 것은 `user_setting.ini` 항목뿐이다. RF 명령이 Wi-Fi나 계정을 지울 수 있는 경로가 없다.
- **RF는 읽고-고치고-쓴다.** 한 필드만 바꾸고 나머지 ini 항목은 그대로 둔다.
- **동시에 살아있지 않다.** 이 모드에서는 RF도 Wi-Fi도 오디오도 시작하지 않는다 (§2.1).

### 4.5 읽기 — 쓰기 전에 확인한다

```text
@GET
@END
```

응답:

```text
@RESULT=OK
@MAC=58e6c5f2cc74
@MODEL=IOT-1000
@P4=V.260823-1
@C6MODEL=IOT-1000C6
@C6=V.260823-1
@SSID=skyiptime7439
@PASSWORD=SET
@SERVER=hanna-aircast.co.kr
@MQTTID=58e6c5f2cc74
@MQTTPW=SET
@ZONE=1
@CHN=1
@COLOR=1
@PIR SENSOR=0
@BATTERY=0
@REBOOT DAY=0
@END
```

**비밀번호는 돌려주지 않는다.** 확인해야 하는 것은 "설정돼 있는가"이지 값이 아니고, 열린 선으로 내보낼 이유가 없다.

| 값 | 뜻 |
|---|---|
| `@PASSWORD=SET` | Wi-Fi 비밀번호가 저장돼 있다 |
| `@PASSWORD=NONE` | 없다 (또는 열린 AP) |
| `@MQTTPW=SET` | 브로커 비밀번호가 저장돼 있다 |
| `@MQTTPW=NONE` | 없다 (익명으로 붙는다) |

식별값(`@MAC` `@MODEL` `@P4` `@C6MODEL` `@C6`)도 같이 돌려준다. 화면의 QR을 못 찍는 상황에서 이 응답으로 대신할 수 있다.

### 4.5.1 `@WIFICLR` — 저장된 Wi-Fi 지우기

```text
> @WIFICLR
> @END
@RESULT=OK
@SSID=
@PASSWORD=NONE
@END
```

**덮어쓰기가 아니라 지우기다.** `@SSID=`를 빈 값으로 보내는 것으로는 안 된다 — 빈 SSID는 거절된다(§5.4). 저장한 적이 없던 상태로 되돌린다.

**`@SSID`/`@PASSWORD`와 같이 보내면 거절한다.** 지운 뒤 넣는 것인지 넣은 뒤 지우는 것인지 순서에 따라 결과가 반대라, 둘 중 하나만 보내게 한다.

```text
> @WIFICLR
> @SSID=village_ap
> @PASSWORD=1234
> @END
@RESULT=FAIL
@ERROR=WIFICLR cannot be sent with SSID/PASSWORD
@END
```

**언제 쓰나** — 출하 전에 라인 AP 정보를 단말에서 빼고 싶을 때다. 설치할 때 `@SSID`/`@PASSWORD`가 어차피 덮어쓰므로 **안 써도 방송에는 지장이 없다.** 공장 비밀번호가 단말에 남는 것이 걸릴 때 쓴다.

`@OFF`와 같이 보내도 된다. 지운 뒤 재부팅한다.

### 4.6 쓰기 — 보낸 것만 바뀐다

| 키 | 필수 | 저장 위치 |
|---|---|---|
| `@SSID` | 쌍 | Wi-Fi NVS |
| `@PASSWORD` | 쌍 | Wi-Fi NVS |
| `@SERVER` | 선택 | `server_cfg` NVS |
| `@MQTTID` | 선택 | `server_cfg` NVS |
| `@MQTTPW` | 선택 | `server_cfg` NVS |
| `@ZONE` (0~99) | 선택 | `user_setting.ini` |
| `@CHN` (0~255) | 선택 | `user_setting.ini` |
| `@COLOR` (0~99) | 선택 | `user_setting.ini` |
| `@PIR SENSOR` (0/1) | 선택 | `user_setting.ini` |
| `@BATTERY` (0/1) | 선택 | `user_setting.ini` |
| `@REBOOT DAY` (0~15) | 선택 | `user_setting.ini` |

**키마다 가는 곳이 다르다.** Wi-Fi 자격증명은 `user_setting.ini`에 쓰지 않는다 - 그 파일은 생산자 설정용이고 비밀번호가 평문으로 남을 자리가 아니다.

**보내지 않은 항목은 건드리지 않는다.** Wi-Fi만, 나머지만, 둘 다 - 어느 쪽으로 보내도 된다. 현장에서는 Wi-Fi만 바꾸는 경우가 대부분이다.

#### SSID와 비밀번호는 한 쌍이다

둘 중 하나만 보내면 거부한다. SSID만 바꾸면 옛 비밀번호가 남아 붙지 못하는데, 화면에는 새 SSID가 보여서 원인을 찾기 어렵다. 열린 AP는 `@PASSWORD=`를 빈 값으로 보낸다.

#### 부분 적용은 하지 않는다

아는 키인데 값을 못 읽으면 **아무것도 저장하지 않고** 어느 키가 문제인지 돌려준다. 절반만 들어간 설정이 현장에서 제일 헷갈린다.

**값 검사는 저장보다 먼저 전부 끝난다.** 그래서 범위를 벗어난 값 하나가 나머지까지 막는다 — 의도한 동작이다.

**다만 저장 자체가 실패하면 그 앞까지는 들어간다**(§5.4의 주석). NVS 쓰기 실패나 계정 길이 초과 같은 경우인데, 사양대로 값을 보내면 생기지 않는다.

모르는 키는 조용히 넘어간다. 앱이 새 키를 보내도 구형 펌웨어가 거부하지 않게 하기 위해서다.

응답은 **적용한 항목만** 돌려준다. 앱이 보낸 것과 대조해 빠진 것을 알 수 있다.

```text
@RESULT=OK
@SSID=village_ap
@PASSWORD=SET
@END
```

실패한 경우:

```text
@RESULT=FAIL
@ERROR=SSID and PASSWORD must be sent together
@END
```

### 4.7 재부팅은 따로 시킨다

저장했다고 바로 재부팅하지 않는다.

```text
@OFF
@END
```

이 명령을 받았을 때만 재부팅한다. 전원을 껐다 켜도 된다.

**나눠 보낼 수 있어야 하기 때문이다.** Wi-Fi를 보내고, 설정을 보내고, `@GET`으로 확인한 뒤 마지막에 끝내는 흐름이 자연스럽다. 첫 저장에서 재부팅해 버리면 그 중간이 끊긴다.

설정과 같이 보내도 된다. 저장한 뒤 재부팅한다.

```text
@ZONE=1
@OFF
@END
```

**저장이 실패하면 재부팅하지 않는다.** 실패를 화면과 응답으로 보고 넘어가야지, 재부팅으로 덮으면 안 된다.

화면에는 저장 후 `send @OFF to reboot`으로 표시해 다음에 무엇을 할지 알린다.

### 4.8 적용 시점

받은 값은 NVS와 `user_setting.ini`에 즉시 저장된다. 다만 **실제로 쓰이는 것은 재부팅 뒤다** - Wi-Fi도 서버 주소도 부팅 때 읽어가기 때문이다. 지금 설정 화면과 같은 흐름이다.

무입력이 이어지면(§2.3) 재부팅하므로, `@OFF`를 잊고 케이블만 뽑아도 결국 적용된다.

### 4.9 설정 화면의 `WIFI(FACT)` 행

**케이블 없이 라인 AP를 넣고 빼는 자리다.** KEY3+KEY4 생산자 설정 화면에 있다.

```text
  WIFI           factory_ap
  SERVER         hanna-aircast.co.kr
> WIFI(FACT)     ON            <- KEY3 ON / KEY4 OFF
```

| 키 | 동작 |
|---|---|
| **KEY3** | **ON** — 지금 AP를 담아 두고 공장 AP로 바꾼다 |
| **KEY4** | **OFF** — 담아 둔 AP로 되돌린다 |

값 열은 **지금 저장된 것이 공장 AP인지**만 보여준다(`ON`/`OFF`). SSID 자체는 바로 위 `WIFI` 행에 나온다.

#### 되돌릴 수 있어야 한다

**켤 때 원래 AP를 잃으면 안 된다.** 그래서 ON은 덮어쓰기가 아니라 **자리 바꾸기**다.

```text
고객집AP  --[KEY3 ON]-->  factory_ap   (고객집AP는 예비 자리로)
factory_ap --[KEY4 OFF]-> 고객집AP     (예비 자리에서 되돌아옴)
```

켜기 전에 저장된 것이 없었으면, 끌 때 **없던 상태로 돌아간다.**

**이미 그 상태면 아무것도 하지 않는다.** ON에서 KEY3을 또 누르면 공장 AP가 예비 자리로 들어가 되돌아갈 곳이 없어지므로, `ALREADY ON`만 표시하고 넘어간다.

`@WIFICLR`은 이것과 다르다 — **되돌리지 않고 지운다.** 예비 자리도 같이 비운다.

**RF INIT처럼 누르는 즉시 실행된다.** 재부팅은 하지 않으므로 다른 항목을 더 만지고 `SAVE`로 나가면 된다.

공장 AP의 SSID와 비밀번호는 **펌웨어에 들어 있다**(`main/core/app_runtime_config.h`). 라인에서 버튼으로 한 글자씩 치지 않게 하려는 것이다. MQTT 계정과 달리 여기에 값을 두는 이유는, 이 AP로 얻을 수 있는 것이 **공장 안 네트워크 접속뿐**이기 때문이다.

```text
@END
```

**`@ZONE`이나 `@SERVER`는 보내지 않았으므로 그대로 남는다.**

### 5.2 여러 항목을 한 번에 넣기

**프로토콜로는 네트워크와 RF·모델 항목을 한 요청에 담을 수 있다.** 아래가 그 예다.

> **다만 서버 등록 모드는 네트워크 항목만 보낸다** — `@SSID` `@PASSWORD` `@SERVER` `@MQTTID` `@MQTTPW` 다섯 줄이다(§6.2).
>
> RF·모델 항목은 **KEY3+KEY4 생산자 설정 경로가 맡는다.** 등록 모드가 같이 보내면 거기서 넣은 값을 덮어쓴다.

```text
> @SSID=factory_ap
> @PASSWORD=test1234
> @SERVER=hanna-aircast.co.kr
> @MQTTID=58e6c5f2cc74
> @MQTTPW=<서버가 발급한 비밀번호>
> @ZONE=1
> @CHN=1
> @COLOR=1
> @PIR SENSOR=0
> @BATTERY=0
> @REBOOT DAY=0
> @OFF
> @END
@RESULT=OK
@SSID=factory_ap
@PASSWORD=SET
@SERVER=hanna-aircast.co.kr
@MQTTID=58e6c5f2cc74
@MQTTPW=SET
@ZONE=1
@CHN=1
@COLOR=1
@PIR SENSOR=0
@BATTERY=0
@REBOOT DAY=0
@END
```

저장하고 바로 재부팅한다.

`@GET` 응답에는 **저장된 전 항목이 실린다** — 보내지 않은 것도 나온다. 서버는 그중 **자기가 보낸 항목만 비교하면 된다**(§6.4).

### 5.3 나머지 설정만 바꾸기

Wi-Fi는 그대로 두고 방송 설정만 손볼 때다.

```text
> @ZONE=3
> @CHN=17
> @END
@RESULT=OK
@ZONE=3
@CHN=17
@COLOR=1
@PIR SENSOR=0
@BATTERY=0
@REBOOT DAY=0
@END
```

`user_setting.ini`는 파일 하나로 저장되므로 **보내지 않은 항목도 현재값 그대로 응답에 실린다.** Wi-Fi와 서버는 건드리지 않았으므로 응답에 없다.

### 5.3.1 브로커 계정만 바꾸기

서버가 계정을 재발급했을 때다. **id와 비밀번호는 한 쌍으로 묶지 않는다** - 한쪽만 바뀌는 경우가 실제로 있고, 안 바뀐 쪽까지 다시 치게 하면 오타가 들어갈 자리만 늘어난다.

```text
> @MQTTPW=<서버가 새로 발급한 비밀번호>
> @END
@RESULT=OK
@MQTTPW=SET
@END
```

빈 값을 보내면 지운다. 익명 접속을 받는 브로커로 옮길 때 쓴다.

```text
> @MQTTID=
> @MQTTPW=
> @END
@RESULT=OK
@MQTTID=
@MQTTPW=NONE
@END
```

계정은 **다음 접속부터** 적용된다. 이미 붙어 있는 세션은 끊지 않으므로, 확실히 하려면 `@OFF`로 재부팅한다.

### 5.4 거부되는 경우

**SSID만 보냈을 때** — 옛 비밀번호가 남아 못 붙는 상태를 막는다.

```text
> @SSID=village_ap
> @END
@RESULT=FAIL
@ERROR=SSID and PASSWORD must be sent together
@END
```

**값이 범위를 벗어났을 때** — 어느 키가 문제인지 돌려준다.

```text
> @ZONE=200
> @END
@RESULT=FAIL
@ERROR=ZONE
@END
```

**SSID가 비었을 때** — 붙을 곳이 없는 설정이다. 비밀번호를 같이 보냈든 안 보냈든 같다. Wi-Fi를 지우려면 `@WIFICLR`을 쓴다(§4.5.1).

```text
> @SSID=
> @PASSWORD=1122222
> @END
@RESULT=FAIL
@ERROR=SSID empty
@END
```

**빈 요청** — `@END`만 온 경우다.

```text
> @END
@RESULT=FAIL
@ERROR=nothing to apply
@END
```

**위 세 경우는 아무것도 저장하지 않고 재부팅하지도 않는다.** 값 검증이 저장보다 먼저 끝나기 때문이다.

> **저장 단계에서 실패하면 그 앞까지는 들어가 있다.** 저장은 Wi-Fi → 서버 주소 → 계정 → 설정 순으로 실행되므로, 중간에 실패하면 앞의 것은 이미 저장된 채 `@RESULT=FAIL`이 나간다.
>
> 여기까지 오는 경우는 **계정 값이 단말 한계(127자, ASCII `0x20`~`0x7E`)를 넘을 때**뿐이다. 사양대로 8자를 발행하면 생기지 않는다. 생기더라도 **같은 요청을 다시 보내면 덮어써진다.**

### 5.5 열린 AP에 붙일 때

비밀번호를 빈 값으로 보낸다. 키 자체를 빼면 §5.4처럼 거부된다.

```text
> @SSID=open_ap
> @PASSWORD=
> @END
@RESULT=OK
@SSID=open_ap
@PASSWORD=NONE
@END
```

### 5.6 모르는 키를 보냈을 때

조용히 무시한다. 앱이 새 키를 보내도 구형 펌웨어가 거부하지 않게 하기 위해서다.

```text
> @ZONE=2
> @FUTURE_FIELD=xyz
> @END
@RESULT=OK
@ZONE=2
@CHN=1
...
@END
```

**응답에 `@FUTURE_FIELD`가 없는 것으로 무시됐음을 안다.**

## 6. 생산 라인 등록 절차 — 서버와 함께

> **전체 흐름은 `DEVICE_REGISTRATION_FLOW_SPEC_2026-08-29.md`에 있다.** 사전 등록·생산·설치·운영 네 단계와 화면 구성이 거기 있고, **여기는 시리얼 구간만** 다룬다.
>
> **HW 검증(스피커·버튼·LCD·PIR·RF)은 등록 이전 단계다.** 서버는 관여하지 않는다.
>
> **Wi-Fi는 거기서 「칩이 살아 있는가」까지만 본다.** 서버 접속과 Wi-Fi 방송은 이 등록 단계에서 처음 시험된다.

이 절은 **그중 생산 라인 부분**을 시리얼 프로토콜 관점에서 적는다.

> **1차 범위 확정 (2026-08-29).** 등록 모드가 보내는 것은 네트워크 5개 항목뿐이다 — `@SSID` `@PASSWORD` `@SERVER` `@MQTTID` `@MQTTPW`. RF·모델 항목은 KEY3+KEY4 기존 경로가 맡는다.
>
> `@WIFICLR`은 **있다**(§4.5.1). 다만 **라인이 직접 쓰는 명령이고 등록 모드는 보내지 않는다** — 라인 Wi-Fi는 설치 때 덮어써지므로 등록 절차에 넣을 이유가 없다.

**등록은 생산 라인에서만 한다.** 케이블이 항상 있으므로 시리얼로 충분하고, 현장용 별도 경로를 만들 필요가 없다.

### 6.1 흐름

```text
[단말]                          [서버 PC — 등록 모드]
플래싱 완료
QR 화면 대기          ──바코드/QR 스캔──▶  MAC·모델·버전 수신
                                          사람이 확인
                                          마을 선택 → village_id
                                          계정 발행
                      ◀────[전송] 버튼────  네트워크 5항목 한 번에
NVS 저장
                      ──────@GET─────────▶  응답 수신
                                          항목별 비교
                                          틀리면 [전송] 다시
                      ◀──────@OFF────────   맞으면 「전송 완료」
재부팅
라인 Wi-Fi 접속
MQTT 접속
STATUS 발행 ───────────────────────────▶  STATUS 도착
                                          「등록 완료」
```

**`@GET` 비교가 끝이 아니다.** `@OFF`를 보내야 단말이 재부팅해 서버에 붙는다 — 안 보내면 단말이 등록 화면에 그대로 멈춰 **배치 목록이 대기에서 안 바뀐다.**

**「등록 완료」는 STATUS가 도착해야 붙는 이름이다.** 1차 비교까지는 「전송 완료」다(§6.5). 1차만으로 완료 처리하면 §6.3이 막으려는 실패가 그대로 현장까지 간다.

케이블이 필요한 것은 여기까지다. **접속 확인과 방송 테스트는 배치로 묶는다** — 기준 문서 §B3.

### 6.2 한 번에 보낸다

**부분 전송을 하지 않는다.** 단말은 하나라도 틀리면 전부 거부하므로(§4.6), 나눠 보내면 어디까지 들어갔는지 알 수 없는 상태가 생긴다.

```text
> @SSID=village_ap
> @PASSWORD=<Wi-Fi 비밀번호>
> @SERVER=hanna-aircast.co.kr
> @MQTTID=58e6c5f2cc74
> @MQTTPW=<서버가 발행한 값>
> @END
```

**네트워크 항목만 보낸다.** `@ZONE` `@CHN` 같은 RF·모델 항목은 KEY3+KEY4 경로가 맡는다(§4.4.1은 그쪽에서 쓰는 목록이다). 등록 모드가 같이 보내면 라인에서 넣은 값을 덮어쓴다.

**Wi-Fi 정보가 빠지면 안 된다.** 없으면 단말이 네트워크에 못 붙어 §6.5의 2차 확인이 불가능하다.

### 6.3 확인은 두 단계다

| 단계 | 방법 | 잡는 것 | 걸리는 시간 |
|---|---|---|---|
| **1차** | `@GET` 응답을 보낸 값과 비교 | 전송 오류, 오조작, 잘림 | 즉시 |
| **2차** | 그 MAC의 STATUS가 서버에 도착 | **계정 자체가 틀림, 브로커 미등록** | 수십 초 |

**1차만으로는 부족하다.** `@GET`이 맞아떨어져도 그것은 "보낸 값이 그대로 들어갔다"까지다. 서버가 발행을 잘못했거나 브로커에 계정을 등록하지 않았으면 **1차는 통과하고 현장에서 실패한다.**

**2차가 진짜 검증이다.** 단말이 그 계정으로 브로커에 붙었다는 것은 **브로커가 이미 비밀번호를 검증했다**는 뜻이다. 서버가 따로 물어볼 필요가 없다.

#### 라인 인터넷은 필수다

**2차 없이 넘기지 않는다.** 2차를 못 하면 단말이 정상인지 모르는 채로 출하하게 되고, 현장에 가서야 알게 된다 — 회수 비용이 든다.

전제 조건은 `DEVICE_REGISTRATION_FLOW_SPEC_2026-08-29.md` §10에 있다.

### 6.4 서버가 할 일

| # | 항목 | 비고 |
|---|---|---|
| 1 | **등록 모드 화면** | 스캔 입력 대기, 한 칸에 QR 문자열 전체를 받는다(§3.2.2) |
| 2 | QR 문자열 분리 | `MAC\|P4모델\|P4버전\|C6모델\|C6버전`. **앞 5개만 해석하고 뒤는 무시** |
| 3 | **마을 선택** → `village_id` | 미리 등록된 마을에서 고른다. 주소 검색은 마을을 만들 때 쓴다 |
| 4 | **계정 발행** | username = 단말 MAC(확정). `SERVER_DEVICE_CREDENTIAL_SPEC_2026-08-27.md` §2 |
| 5 | **[전송] 버튼** | 시리얼로 §6.2 형식을 그대로 보낸다 |
| 6 | **`@GET` 실행과 비교** | 아래 |
| 7 | 등록 완료 처리 | DB에 **MAC·village_id·계정** 저장. 주소·이름은 사무실에서 채운다 |
| 8 | **2차 확인 표시** | 그 MAC의 STATUS 도착 여부를 등록 목록에 |

**5·6번은 서버 PC가 시리얼 포트를 직접 다룬다.** 스캐너와 시리얼 케이블이 같은 PC에 붙는다.

#### 6번 비교 규칙

| 항목 | 비교 |
|---|---|
| `@SSID` `@SERVER` `@MQTTID` | **값 그대로** 비교 |
| `@PASSWORD` `@MQTTPW` | **보낸 값이 비었으면 `NONE`, 값이 있으면 `SET`.** 아래 |
| `@MAC` | 스캔한 MAC과 같은가 — **다른 단말에 꽂았는지** 잡는다 |

**`@MAC` 비교를 빠뜨리면 안 된다.** 여러 대를 연달아 작업할 때 케이블을 옆 단말에 꽂는 실수가 실제로 난다. 이 비교가 그것을 잡는 유일한 지점이다.

### 6.5 등록 상태

서버 등록 목록에 단말별로 남긴다.

| 상태 | 뜻 | 다음 |
|---|---|---|
| 미등록 | 스캔은 됐으나 전송 전 | [전송] |
| **전송 완료** | 1차 통과, STATUS 아직 없음 | 기다린다 |
| **등록 완료** | 2차까지 통과 | 없음 |
| **불일치** | `@GET` 비교 실패 | [전송] 다시. 반복되면 케이블·단말 확인 |
| **미접속** | 전송 후 오래 STATUS 없음 | 현장 확인 |

### 6.6 왜 이 설계인가

**서버가 단말에 일방적으로 밀어 넣고 확인하지 않는 방식**도 가능하다. 그러나 오타 하나가 그대로 통과하고, **현장에 설치한 뒤에야 드러난다.** 마을 가정집에 설치된 단말을 다시 찾아가는 비용이 크다.

`@GET` 비교는 **라인에서 즉시 잡는다.** 비용은 명령 한 번이다.

**비밀번호는 값을 돌려주지 않는다.** 라인 PC 화면과 로그에 평문이 남기 때문이다. `SET`은 「들어갔다」까지만 말한다.

**값이 맞는지는 2차가 증명한다.** 단말이 그 계정으로 브로커에 붙었다는 것은 브로커가 이미 검증했다는 뜻이다. 그래서 **단말이 값을 되돌려주게 만들지 않는다** — 열린 선에 비밀번호를 흘리면서 얻을 것이 없다.

## 7. 보안

케이블을 꽂을 수 있으면 누구나 설정을 바꿀 수 있다.

**이것을 허용한다.** 마을 방송함은 물리 접근 자체가 통제되고, 지금의 부팅 콤보와 같은 수준이다. 부팅 콤보를 눌러야 이 모드에 들어가므로 운영 중 단말이 케이블 노이즈를 설정으로 오인할 일도 없다.

더 조여야 한다면 페이로드에 공유 비밀을 넣는 방법이 있으나, 그 값이 앱에 박히므로 실효가 크지 않다. **지금은 넣지 않는다.**

브로커 계정도 이 선으로 오간다. 다만 **`@GET`은 비밀번호를 돌려주지 않는다** — `SET`이거나 `NONE`뿐이다(§4.4.1). 실제 방어는 브로커 ACL이 맡는다 - `SERVER_COMM_MQTT_ICECAST_HTTP_SPEC_2026-08-14.md` §2.1.

## 8. 구현 순서

앞의 것이 뒤의 것 없이도 쓸모가 있도록 나눈다.

| 단계 | 내용 | 이것만으로 되는 일 |
|---|---|---|
| 1 | 콤보 + 전용 화면 + SDIO 기동 | 화면에서 MAC/모델/버전을 눈으로 확인 |
| 2 | 바코드 + QR | **생산 등록에 바로 투입** |
| 3 | 로그 차단 + READY 배너 + UART 수신 | **터미널로 손으로 쳐서 설정 투입** |
| 4 | 화면 결과 표시 + 재부팅 | 현장 설정 완성 |

**2단계까지가 급하다.** MAC 오타는 지금도 나고 있고, 없애는 비용이 Kconfig 두 개와 화면 하나다.

**3단계에서 이미 쓸 수 있다.** 프로토콜이 텍스트라 앱이 없어도 터미널로 `@SSID=...` `@END`를 쳐서 넣을 수 있다. 앱 개발과 단말 개발이 서로를 기다리지 않는다.

## 8.1 구현하면서 알게 된 것

사양에는 없었지만 실제로 걸린 것들이다. 다시 비슷한 모드를 만들 때 같은 데서 막히지 않도록 남긴다.

- **`sdio_rpc_init()`만으로는 C6와 통신이 안 된다.** esp-hosted 전송 계층이 서 있어야 하는데, 일반 부팅에서는 Wi-Fi를 올리는 과정에 딸려 온다. 이 모드는 Wi-Fi를 건너뛰므로 `esp_hosted_init()`과 **`esp_hosted_connect_to_slave()`** 를 직접 불러야 한다. 후자가 실제 링크를 맺는다 - 부르지 않으면 `Req_CustomRpc` 타임아웃만 반복된다.
- **부팅 중 UART에 쌓인 바이트가 첫 요청을 망친다.** 터미널을 미리 열어두었거나 케이블을 꽂는 순간의 잡음이 FIFO에 남아 첫 줄 앞에 붙고, 그 줄이 `@`로 시작하지 않아 통째로 버려진다. 첫 `@GET`이 "nothing to apply"로 돌아오는 증상이었다. 포트를 열 때 `uart_flush_input()`을 하고, 버퍼가 비어 있을 때는 `@`가 아닌 바이트를 담지 않는다.
- **HELLO의 모델 필드를 꽉 채우면 잘렸다.** 보내는 쪽이 받는 쪽에 필요 없는 종료 문자 자리를 남기고 있었다. 8바이트 필드에 8자를 넣으면 7자만 갔다. 지금은 필드가 16바이트이고 길이를 빌드에서 확인한다.

## 9. 정해진 것과 남은 것

### 정해진 것

| 항목 | 결정 |
|---|---|
| 진입 | `KEY1+KEY4` 부팅 콤보 (§2) |
| 이 모드에서 도는 것 | 화면 + SDIO RPC만. Wi-Fi/RF/오디오 없음 (§2.1) |
| 화면 배치 | 왼쪽 P4 값 + 바코드, 오른쪽 C6 값 + QR (§3) |
| QR 내용 | `MAC\|P4모델\|P4버전\|C6모델\|C6버전`, 구분자 `\|` (§3.2) |
| 등록 방식 | **B — 입력칸 하나에 받고 서버가 쪼갠다** (§3.2.1) |
| 스캐너 접미사 | Enter (기본값 그대로) |
| 시리얼 프로토콜 | `user_setting.ini`와 같은 `@KEY=VALUE` + `@END` (§4.4) |
| 명령 | 전체 목록은 §4.4.1. `@GET` 읽기, `@OFF` 재부팅, 그 외는 쓰기 |
| 쌍으로 보내야 하는 것 | `@SSID` + `@PASSWORD`. **브로커 계정은 묶지 않는다** |
| 채널 키 이름 | `@CHN` (RF의 `@R,CHN=`과 맞춤). `@CHANNEL`도 계속 읽는다 (§4.4.1) |
| 브로커 계정 | `@MQTTID` / `@MQTTPW`. 원본은 P4 NVS, C6에는 SERVER_CFG로 내려감 |
| 비밀번호 확인 | `@GET`이 `SET`/`NONE`만 돌려준다 (§4.4.1). **체크섬은 쓰지 않는다** |
| 등록 절차 | 생산 라인에서만. 1차 `@GET` 비교 + 2차 STATUS 도착 (§6) |
| 빠진 항목 | 건드리지 않고 기존 값 유지 |
| 모르는 키 | 무시 |
| 저장 실패 | 아무것도 저장하지 않고 재부팅도 안 함 |
| `@PASSWORD`/`@MQTTPW` 공백 | 다듬지 않는다. 나머지 키는 다듬는다 (§4.4) |
| Wi-Fi 지우기 | `@WIFICLR` (§4.5.1). 설정 화면은 `WIFI(FACT)` 행 (§4.9) |
| CRC | **사용하지 않는다** (§4.4 무결성) |

### 서버에 요청할 것

등록 화면에 **문자열 하나를 받는 입력칸**을 두고, Enter가 들어오면 `\|`로 쪼개 각 항목에 배치한다. 상세는 §3.2.2.

**앞 5개만 해석하고 뒤는 무시하도록** 만들어 달라고 요청한다. 나중에 QR에 항목이 늘어도 서버가 깨지지 않는다.

### 남은 것

단말 쪽은 없다. 아래는 운영에서 정하거나 확인할 것들이다.

| # | 항목 | 비고 |
|---|---|---|
| 1 | 2D 스캐너 확보 | 지금 쓰는 1D로 QR이 읽히는지부터 확인. 안 되면 §3.2.4 |
| 2 | **서버 등록 모드 화면과 [전송] 버튼** | §6.4. QR 분리 코드 포함(§3.2.2) |
| 3 | 무입력 타임아웃 시간 | 지금 10분(§2.3). 현장에서 써 보고 판단 |
| 4 | QR에 항목을 더 넣을 것인가 | 생산 일련번호, 제조일 등. 넣으면 서버는 그대로 두면 된다(앞 5개만 해석) |
