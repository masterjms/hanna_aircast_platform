xWIFI 운영서버 화면 설계 (v1)

API(`xWIFI_API_설계_260815.md`) 위에서 화면을 잡는다. 80점 기준 — 레이아웃 구조와 화면당 핵심 요소만 정리하고, 실제 디자인(색/폰트/컴포넌트 디테일)은 구현 단계에서 정한다.

## 공통 레이아웃

```
+------------------------------------------------------+
| xWIFI 로고        [담당: OO마을 외 2곳]      [로그아웃] |
+--------+-----------------------------------------------+
| 대시보드 |                                               |
| 단말관리 |                                               |
| 방송제어 |               (화면별 내용)                    |
| 파일함  |                                               |
| 이력   |                                               |
| 스케줄  |                                               |
| 비용   |                                               |
| OTA*   |                                               |
| 설정*   |                                               |
| 마을*   |                                               |
| 계정*   |                                               |
+--------+-----------------------------------------------+
```

`*` 표시(OTA/설정/마을관리/계정관리)는 super_admin 전용 메뉴 — village_admin 로그인 시 사이드바에서 아예 숨긴다. 상단에 로그인한 계정의 담당 마을 범위를 항상 표시해서, "지금 내가 어디까지 보고 있는지" 헷갈리지 않게 한다.

## 3. 단말 관리

```
+------------------------------------------------------+
| [마을: 전체 v] [구역: 전체 v] [상태: 전체 v]  [+ 단말등록] |
+------------------------------------------------------+
| MAC          별칭      마을    구역    상태   RSSI  ... |
| 58e6c5f2cc74 정자스피커1 OO리   정자    온라인  -34  [상세]|
| ...                                                    |
+------------------------------------------------------+
| 미배정 단말 (2)                                          |
| a1b2c3d4e5f6  (마을/구역 배정 대기)        [배정하기]     |
+------------------------------------------------------+
```

상세(모달/서브페이지): 별칭·마을·구역 수정, 최근 STATUS/LIVE_STATS 그래프, 최근 이벤트 이력.

"상태" 컬럼은 STATUS의 `state` 값(IDLE/LIVE/FILE/RF/OTA/OFFLINE, §통신 사양 참고)을 그대로 보여주면 된다. 2026-08-20부터 단말이 상태 변경 시 즉시 STATUS를 발행하므로, 이 컬럼과 §2 대시보드의 "방송중"/"OTA 중" 배지는 주기(최대 status_interval_sec)를 기다리지 않고 거의 실시간으로 갱신된다.

**대시보드 지도·목록 보완 (2026-09-03)**: 지도에 줌 ± 컨트롤과 마커 클러스터러(멀리서 볼 때 겹치는 핀을 숫자로 묶음)를 넣었다. 왼쪽 단말 목록에서 단말을 고르면 지도가 그 단말로 확대·이동한다. 목록은 마을 사이에만 구분선을 두고 단말 행은 촘촘하게 붙였으며, 왼쪽 칼럼은 타일·목록·이상단말을 세로로 고정 배치해 **단말이 늘어도 페이지가 길어지지 않고 목록만 안에서 스크롤**한다. 상세는 지도 설계 §4.5·§4.9.

## 4. 방송 제어

```
+------------------------------------------------------+
| 대상: (o)마을  ( )구역  ( )개별  ( )전체                 |
+------------------------------------------------------+
| 마을 (여러 곳 선택 가능)                                 |
|   [v] 신동마을 (온라인 12대)                             |
|   [v] 하회마을 (온라인 6/8대)      <- 일부 꺼짐, 강조표시   |
|   [ ] 양동마을 (전부 오프라인 · 5대) <- 선택 불가          |
|   선택한 2개 마을이 같은 방송을 동시에 받습니다.            |
+------------------------------------------------------+
| [ 실시간 방송 시작 ]   [ 실시간 방송 종료 ]                |
+------------------------------------------------------+
| 파일 선택 [notice.mp3 v]  [ 파일 방송 시작 ]  [ 중지 ]     |
+------------------------------------------------------+
| 진행 상황: 대상 20대 중 준비완료 18 / 실패 0 / 대기 2      |
+------------------------------------------------------+
```

**대상은 다중 선택이다**(2026-08-24). 운영에서 요구된 네 시나리오가 전부 "소리 하나를 여러 단말에 보내는 것"이고, 다른 건 대상 집합뿐이기 때문이다:

| 시나리오 | 선택 |
|---|---|
| 마을 1곳 | 마을 · 체크 1개 |
| 마을 여러 곳 동시 | 마을 · 체크 여러 개 |
| 한 마을에서 단말 몇 대만 | 개별 · 단말 체크 여러 개 |
| 전체 | 전체 |

- **마을**은 체크박스 목록(다중). **개별**은 마을로 목록을 거른 뒤 단말 체크박스(다중), 오프라인 단말은 비활성.
- **구역**은 단일 선택을 유지한다(다중 구역 요구가 아직 없다).
- 혼합 대상("마을 1 전체 + 마을 2의 단말 3대")은 **지원하지 않는다** — 요구에 없어서 구조를 단순하게 뒀다.
- 마을을 여러 곳 골라도 **방송은 1건**이다. job_id도 마운트도 마이크도 하나이고, 서버가 대상 마을 토픽마다 같은 명령을 내보낸다.

**대수는 등록이 아니라 온라인 기준으로 보여준다**(2026-08-24). 방송은 온라인 단말에만 나가므로, 등록 대수만 표시하면 운영자가 "3대에 나가겠구나" 하고 눌렀는데 1대만 나가는 일이 생긴다. 표시 규칙:

| 상태 | 표시 | 선택 |
|---|---|---|
| 전부 온라인 | `(온라인 12대)` | 가능 |
| 일부 꺼짐 | `(온라인 6/8대)` — 강조색 | 가능 |
| 전부 꺼짐 | `(전부 오프라인 · 5대)` — 경고색 | **불가** |
| 단말 없음 | `(단말 없음)` | 불가 |

마을·구역 모두 같은 규칙을 쓴다. 온라인 판정은 서버 한 곳(`app/core/presence.py`)에서만 정의한다 — 판정이 두 벌이면 화면마다 다른 말을 한다.

**무음 경고**: 실시간 방송 중 마이크가 안 붙어 있으면 경고를 띄우고, 30초 안에 끝내 안 붙으면 서버가 방송을 자동 종료한다(ON AIR로 보이는데 소리가 안 나가는 상태를 막는다).

**진행 상황 막대와 종료 표시 (2026-09-02, 문제점 리스트 3·4·5·6번)**

- 주황색 막대 = `(성공 + 실패) / 발행 시점 대상 대수`, 즉 **응답이 온 비율**이지 성공률이 아니다. 막대에 마우스를 올리면 `응답 n / m대 (성공 x · 실패 y)`가 뜬다.
- 파일 방송은 단말이 재생을 마치면(`FILE_RESULT`) 서버가 스스로 종료 처리한다. 예전에는 사람이 [중지]를 누를 때까지 화면이 계속 "송출 중"이었다.
- [중지]를 누르면 버튼이 `중지 중…`으로 바뀌고 비활성화되며, `중지를 보냈습니다. 단말의 종료 응답을 기다리는 중입니다 (n/m대 응답)` 안내가 뜬다. 응답이 다 오면 즉시, 늦으면 설정한 대기 시간(10~30초) 뒤에 종료된다.
- 라이브 방송이 시작되고 설정한 시간(기본 10초)이 지나도 준비되지 않은 단말이 있으면 `n초가 지났는데 k대가 아직 준비되지 않았습니다. 그대로 방송할지, 더 기다릴지, 중지할지 선택하세요.`를 띄운다. 서버가 대신 판단하지 않는다 — 마이크는 이미 열려 있고, 몇 대가 빠진 채 방송할지는 방송하는 사람이 정할 일이다.

## 5. 파일 라이브러리

```
+------------------------------------------------------+
| [ 파일 업로드 ]   [ 문장으로 만들기(TTS) ]                |
+------------------------------------------------------+
| 파일명            길이   생성방식   [미리듣기] [방송] [삭제] |
| notice.mp3        0:32  업로드     ...                 |
| tts_1234.mp3       0:08  TTS(한국어) ...                |
+------------------------------------------------------+
```

TTS 생성 폼(모달, 2026-09-02 단순화): 화면 하나로 끝낸다. 하단 버튼 줄은 아예 없다.

```
+------------------------------------------------------+
| TTS 음성 만들기                                 [닫기] |
+------------------------------------------------------+
| 방송 문구  [________________________________]         |
| 0 / 1000자                                            |
| 언어 [한국어 v]         보이스 [여성 A v]              |
| 파일 이름 [_____________]      [ 음성 만들기 ]         |
|                                                      |
|  -- 만든 뒤: 위 입력은 전부 잠기고 버튼도 비활성 --     |
|  +------------------------------------------------+  |
|  | pop2.mp3                               1.3초    |  |
|  | [ ▶ 재생바 ]                                    |  |
|  | 들어보고 저장하면 파일함에 등록됩니다.            |  |
|  |              [ 음성 저장하기 ]                   |  |
|  +------------------------------------------------+  |
+------------------------------------------------------+
```

- **[음성 만들기]는 파일 이름 입력란 옆에 둔다.** 하단 버튼 줄을 없앴으므로 만들기 동작이 입력 흐름의 끝에 바로 붙는다.
- **한 번 만들면 입력을 잠근다.** 문구·언어·보이스·파일 이름이 모두 비활성이 되고 [음성 만들기]도 비활성이 된다. 문구를 고쳤는데 아래 음원은 예전 것인 상태가 생기면 들은 것과 저장되는 것이 달라지기 때문이다. 다시 만들려면 닫고 새로 연다.
- **[음성 저장하기]를 눌러야 파일함에 남는다.** 서버는 합성하는 즉시 파일 행을 만들지만(별도 저장 단계가 없다), 저장 없이 닫으면 화면이 그 파일을 지운다(`DELETE /api/files/:id`). 들어보고 버린 음성이 파일함에 쌓이지 않게 하기 위해서다. 단, 기존 합성본을 재사용한 경우(`cached=true`)는 지우지 않는다 — 전부터 쓰던 파일을 이 화면이 지우면 안 된다.

## 6. 이력

```
+------------------------------------------------------+
| 기간 [____ ~ ____]  마을[전체 v]  타입[전체 v]  [조회]    |
+------------------------------------------------------+
| 시각    타입        대상     결과              상세       |
| 10:32  FILE_START   OO마을   8/10 성공          [보기]    |
| 10:15  LIVE_STOP    전체     완료               [보기]    |
+------------------------------------------------------+
```

상세: 그 이벤트에 대해 각 단말이 보낸 결과(device_events) 목록.

## 7. 자동방송 스케줄

```
+------------------------------------------------------+
| 등록된 스케줄 (3/10)                        [+ 규칙 추가] |
+------------------------------------------------------+
| 1,2,3월 · 토 · 10:00,16:00 · 대상:전체 · notice.mp3 [끄기][삭제] |
+------------------------------------------------------+
```

규칙 추가 폼: 월(다중선택 체크박스) / 요일(다중선택) / 시각(다중, + 버튼으로 추가) / 파일 선택 / 대상 선택.

## 8. 비용

```
+------------------------------------------------------+
| 마을 [전체 v]   기간 [____ ~ ____]                       |
+------------------------------------------------------+
| (super_admin, 마을=전체일 때만) AWS 실비용(참고, 일별)      |
|  8/10  1,240원   8/11  1,180원   ...   합계 8,930원      |
+------------------------------------------------------+
| 마을별 추정 비용 (사용량 기반 추정치 — 실제 청구액과 다를 수 있음)|
| 마을     방송시간(분)   추정전송량(MB)   추정비용(원)         |
| OO리     120          21.6           약 250원           |
| XX리      80          14.4           약 170원           |
+------------------------------------------------------+
```

village_admin은 마을 드롭다운이 자기 담당 마을로 고정되고(§역할별 권한), 상단 "AWS 실비용" 패널 없이 마을별 추정 비용 표만 본다. 값은 일 1회 배치가 갱신하며(§운영서버 개요의 "비용 조회 기능" 참고), 화면에서 즉시 재계산하지 않는다.

## 9. OTA 관리 (super_admin)

```
+------------------------------------------------------+
| pkg 업로드: [IOT_RADIO.pkg] size=1.6MB sha256=...       |
| 방송 대상: (o)전체 ( )마을[..v] ( )개별[검색]              |
| [ OTA 시작 ]                                            |
+------------------------------------------------------+
| job#5  대상10대  DOWNLOADING 3대/VERIFYING 1대/COMPLETED 5대/FAIL 1대 |
|   [상세]                                                |
+------------------------------------------------------+
```

2026-08-20부터 OTA_APPLY가 폐지되어 "적용 승인" 버튼은 없다 — 단말이 다운로드/검증(COMPLETED)까지 확인되면 관리자 개입 없이 곧바로 적용+재부팅까지 자동 진행한다. 화면은 진행 상태(주로 DOWNLOADING/VERIFYING/COMPLETED/FAIL 집계)를 보여주기만 하고, 최종 성공 여부는 재부팅 후 단말이 다시 접속했을 때의 STATUS 펌웨어 버전으로 판단해 job 목록에 반영한다.

OTA 진행 중인 단말은 3(단말관리)·4(방송제어) 화면에서 "OTA 중" 배지 표시 + 방송 버튼 비활성화.
