xWIFI 운영서버 화면 설계 (v1)

API(`xWIFI_API_설계_260815.md`) 위에서 화면을 잡는다. 80점 기준 — 레이아웃 구조와 화면당 핵심 요소만 정리하고, 실제 디자인(색/폰트/컴포넌트 디테일)은 구현 단계에서 정한다.

## 공통 레이아웃

```
+------------------------------------------------------+
| xWIFI 로고        [담당: OO마을 외 2곳]      [로그아웃] |
+--------+-----------------------------------------------+
| 대시보드 |                                               |
| 단말관리 |                                               |
| 방송제어 |               (화면별 내용)                    |
| 파일함  |                                               |
| 이력   |                                               |
| 스케줄  |  (2026-09-09 구현)                             |
| 비용   |                                               |
| OTA*   |                                               |
| 설정*   |                                               |
| 마을*   |                                               |
| 계정*   |                                               |
+--------+-----------------------------------------------+
```

`*` 표시는 계층이 필요한 메뉴다 — 못 미치는 계정에게는 사이드바에서 아예 숨긴다. **2026-09-08 계층, 09-12 v2** ([관리자 계층 설계](xWIFI_관리자_계층_설계_260908.md)): OTA·설정은 최고 관리자, 지역 관리·계정 관리는 기관 관리자 이상. 상단에 로그인한 계정의 범위(기관 이름 또는 담당 마을)를 항상 표시해서, "지금 내가 어디까지 보고 있는지" 헷갈리지 않게 한다.

## 3. 단말 관리

```
+------------------------------------------------------+
| [마을: 전체 v] [구역: 전체 v] [상태: 전체 v]  [+ 단말등록] |
+------------------------------------------------------+
| MAC          별칭      마을    구역    상태   RSSI  ... |
| 58e6c5f2cc74 정자스피커1 OO리   정자    온라인  -34  [상세]|
| ...                                                    |
+------------------------------------------------------+
| 미배정 단말 (2)                                          |
| a1b2c3d4e5f6  (마을/구역 배정 대기)        [배정하기]     |
+------------------------------------------------------+
```

상세(모달/서브페이지): 별칭·마을·구역 수정, 최근 STATUS/LIVE_STATS 그래프, 최근 이벤트 이력.

"상태" 컬럼은 STATUS의 `state` 값(IDLE/LIVE/FILE/RF/OTA/OFFLINE, §통신 사양 참고)을 그대로 보여주면 된다. 2026-08-20부터 단말이 상태 변경 시 즉시 STATUS를 발행하므로, 이 컬럼과 §2 대시보드의 "방송중"/"OTA 중" 배지는 주기(최대 status_interval_sec)를 기다리지 않고 거의 실시간으로 갱신된다.

**대시보드 지도·목록 보완 (2026-09-03)**: 지도에 줌 ± 컨트롤과 마커 클러스터러(멀리서 볼 때 겹치는 핀을 숫자로 묶음)를 넣었다. 왼쪽 단말 목록에서 단말을 고르면 지도가 그 단말로 확대·이동한다. 목록은 마을 사이에만 구분선을 두고 단말 행은 촘촘하게 붙였으며, 왼쪽 칼럼은 타일·목록·이상단말을 세로로 고정 배치해 **단말이 늘어도 페이지가 길어지지 않고 목록만 안에서 스크롤**한다. 상세는 지도 설계 §4.5·§4.9.

**생산 라인 Wi-Fi 주입 (2026-09-08, 문제점 35번)**: 신규 단말 등록 팝업의 서버 주소 아래에 생산 라인 공유기 SSID·비밀번호를 넣는 칸을 둔다. 둘 다 채워져 있으면 시리얼 주입 프레임 맨 앞에 `@SSID`·`@PASSWORD` 를 함께 보내고, 하나라도 비면 그 줄을 아예 넣지 않는다(빈 값을 보내면 단말에 저장된 기존 Wi-Fi 설정을 지운다). 라인에서 여러 대를 연달아 등록하므로 입력값은 지울 때까지 기억한다 — 작업 PC 의 localStorage 에만 남고 서버로는 보내지 않는다. `@SSID`·`@PASSWORD` 는 생산 serial protocol 에 원래 있는 키라 단말 쪽 변경이 없다.

**바코드 입력은 IME 상태와 무관해야 한다 (2026-09-05, 09-07 보완 — 문제점 20번)**: 신규 단말 등록의 스캔 입력란은 한글 IME가 켜져 있으면 스캐너의 영문 키가 자모로 조합돼 전부 깨졌다. 문자가 아니라 **물리 키(`KeyboardEvent.code`)로 직접 조립**한다. QR 내용은 영문·숫자·`|:-._`뿐이라 그 키만 받고, 방향키 등은 브라우저에 맡긴다.

여기까지로는 부족했다(09-06 재확인: `abcdef` → `aㅁb뮤c뮻d뮻ㅇeㅇㄷfㄷㄹ`). keydown에서 `preventDefault`를 해도 IME는 막히지 않는다 — 자기 조합 결과를 입력칸에 따로 밀어 넣기 때문에 우리가 넣은 글자와 섞여 나온다. 그래서 입력칸을 **편집 불가(readonly)** 로 두고 값은 React 상태로만 채운다. 편집 불가 필드에는 IME가 조합해 넣을 대상 자체가 없다. 붙여넣기는 `paste` 이벤트에서 직접 읽어 처리하므로 그대로 된다.

## 4. 방송 제어

```
+------------------------------------------------------+
| 대상: (o)기관·마을  ( )구역  ( )개별 단말  ( )전체        |
+------------------------------------------------------+
| 기관을 체크하면 아래 마을 전체가 선택됩니다   [선택 해제]   |
| [검색: 마을·기관 이름                              ]    |
| ▾ [v] 경기도            마을 3곳 · (온라인 20/22대)       |
|   ▾ [v] 안양시          마을 2곳                        |
|       [v] 신동마을 (온라인 12대)                         |
|       [v] 하회마을 (온라인 6/8대)  <- 일부 꺼짐, 강조표시   |
|     [v] 산본마을 (온라인 2대)                            |
| ▾ [-] 충청남도          <- 아래만 골랐다(직접 체크 아님)   |
|       [ ] 양동마을 (전부 오프라인 · 5대) <- 선택 불가      |
|       [v] 금산마을 (온라인 4대)                          |
|   대상: 경기도 전체, 금산마을 · 마을 4곳이 동시에 받습니다  |
+------------------------------------------------------+
| 구역·개별 단말도 같은 트리다(2026-09-20)                  |
| ▸ [ ] 경기도                                           |
|   ▾ [-] 산본마을        단말 4개 · (온라인 3/4대)         |
|       [v] 회관 앞 · 마을회관                             |
|       [ ] 경로당               <- 오프라인, 선택 불가     |
+------------------------------------------------------+
| [ 실시간 방송 시작 ]   [ 실시간 방송 종료 ]                |
+------------------------------------------------------+
| 파일 선택 [notice.mp3 v]  [ 파일 방송 시작 ]  [ 중지 ]     |
+------------------------------------------------------+
| 진행 상황: 대상 20대 중 준비완료 18 / 실패 0 / 대기 2      |
+------------------------------------------------------+
```

**진행 중 카드는 마을 이름으로 쓴다 (2026-09-07, 문제점 33번)**: 머리말에 `village 5, 6` 처럼 내부 id가 보이면 방송하는 사람이 어느 마을인지 알 수 없다. 서버가 내려주는 `target_label`(마을·구역·단말 이름, 전체는 「모든 마을」)을 그대로 쓴다. 이력 목록과 대시보드의 진행 중·최근 이력도 같은 값을 쓴다.

**대상은 다중 선택이다**(2026-08-24). 운영에서 요구된 네 시나리오가 전부 "소리 하나를 여러 단말에 보내는 것"이고, 다른 건 대상 집합뿐이기 때문이다:

| 시나리오 | 선택 |
|---|---|
| 마을 1곳 | 마을 · 체크 1개 |
| 마을 여러 곳 동시 | 마을 · 체크 여러 개 |
| 상위 기관 아래 마을 전체 (예: 경기도 전체) | 기관·마을 · 기관 칸 체크 (2026-09-15) — 아래 마을 전부가 체크되고 서버에는 마을 목록으로 간다. 기관 관리자는 자기 기관이 트리 맨 위 |
| 한 마을의 단말 몇 대 · 구역 | 같은 트리에서 마을을 펼쳐 단말·구역 체크 (2026-09-20). 마을 칸을 체크하면 그 마을 전체 |
| 이름으로 찾기 | 트리 위 검색창 — 기관·마을·구역·단말 이름이 걸리는 가지만 남기고 펼친다 |

**상위 기관 체크의 뜻(2026-09-20 정정).** 기관 칸은 **직접 체크했을 때만** 체크로 보인다. 아래 마을만 고른 경우에는 중간 표시(−)다. 「아래가 전부 선택됨」을 체크로 표시하던 때는, 선택 가능한 마을이 하나뿐인 기관에서 그 마을만 골라도 상위 기관이 함께 선택된 것처럼 보여 오해를 샀다(향후검토 7번).
| 한 마을에서 단말 몇 대만 | 개별 · 단말 체크 여러 개 |
| 전체 | 전체 |

- **마을**은 체크박스 목록(다중). **개별**은 마을로 목록을 거른 뒤 단말 체크박스(다중), 오프라인 단말은 비활성.
- **구역**은 단일 선택을 유지한다(다중 구역 요구가 아직 없다).
- 혼합 대상("마을 1 전체 + 마을 2의 단말 3대")은 **지원하지 않는다** — 요구에 없어서 구조를 단순하게 뒀다.
- 마을을 여러 곳 골라도 **방송은 1건**이다. job_id도 마운트도 마이크도 하나이고, 서버가 대상 마을 토픽마다 같은 명령을 내보낸다.

**대수는 등록이 아니라 온라인 기준으로 보여준다**(2026-08-24). 방송은 온라인 단말에만 나가므로, 등록 대수만 표시하면 운영자가 "3대에 나가겠구나" 하고 눌렀는데 1대만 나가는 일이 생긴다. 표시 규칙:

| 상태 | 표시 | 선택 |
|---|---|---|
| 전부 온라인 | `(온라인 12대)` | 가능 |
| 일부 꺼짐 | `(온라인 6/8대)` — 강조색 | 가능 |
| 전부 꺼짐 | `(전부 오프라인 · 5대)` — 경고색 | **불가** |
| 단말 없음 | `(단말 없음)` | 불가 |

마을·구역 모두 같은 규칙을 쓴다. 온라인 판정은 서버 한 곳(`app/core/presence.py`)에서만 정의한다 — 판정이 두 벌이면 화면마다 다른 말을 한다.

**무음 경고**: 실시간 방송 중 마이크가 안 붙어 있으면 경고를 띄우고, 30초 안에 끝내 안 붙으면 서버가 방송을 자동 종료한다(ON AIR로 보이는데 소리가 안 나가는 상태를 막는다).

**진행 상황 막대와 종료 표시 (2026-09-02, 문제점 리스트 3·4·5·6번)**

- 주황색 막대 = `(성공 + 실패) / 발행 시점 대상 대수`, 즉 **응답이 온 비율**이지 성공률이 아니다. 막대에 마우스를 올리면 `응답 n / m대 (성공 x · 실패 y)`가 뜬다.
- 방송 카드 머리말은 서버가 보는 **국면**을 그대로 쓴다(2026-09-03, 문제점 10번): 라이브 `준비 중 → 송출 중 → 중지 중`, 파일 `전송 중 → 재생 중(저장만이면 저장 완료) → 중지 중`. 파일은 단말이 저장을 마치면(`FILE_RESULT ok=true`) 그때 재생이 시작되므로 「재생 중」으로 넘어가고, 재생 길이 뒤에 서버가 스스로 종료 처리한다. 예전에는 사람이 [중지]를 누를 때까지 화면이 계속 "송출 중"이었고, 그다음 고친 버전은 저장 완료 순간에 끝내서 스피커가 나오는 중에 「종료」였다.
- [중지]를 누르면 버튼이 `중지 중…`으로 바뀌고 비활성화되며, `중지를 보냈습니다. 단말의 종료 응답을 기다리는 중입니다 (n/m대 응답)` 안내가 뜬다. 응답이 다 오면 즉시, 늦으면 설정한 대기 시간(10~30초) 뒤에 종료된다. 라이브는 **그때 스트림을 닫는다** — 대기 중에도 mount는 살아 있다(단말이 정지 명령을 받고 스스로 끊게 하기 위해서다).
- 라이브 방송이 시작되고 **설정한 준비 제한 + 5초**(기본 30+5=35초 — +5는 단말이 더 기다리는 펌웨어 상수)가 지나도 준비되지 않은 단말이 있으면 `n초가 지났는데 k대가 아직 준비되지 않았습니다. 그대로 방송할지, 더 기다릴지, 중지할지 선택하세요.`를 띄운다. 서버가 대신 판단하지 않는다 — 마이크는 이미 열려 있고, 몇 대가 빠진 채 방송할지는 방송하는 사람이 정할 일이다.

## 5. 파일 라이브러리

```
+------------------------------------------------------+
| [ 파일 업로드 ]   [ 문장으로 만들기(TTS) ]                |
+------------------------------------------------------+
| 파일명            길이   생성방식   [미리듣기] [방송] [삭제] |
| notice.mp3        0:32  업로드     ...                 |
| tts_1234.mp3       0:08  TTS(한국어) ...                |
+------------------------------------------------------+
```

TTS 생성 폼(모달, 2026-09-02 단순화): 화면 하나로 끝낸다. 하단 버튼 줄은 아예 없다.

```
+------------------------------------------------------+
| TTS 음성 만들기                                 [닫기] |
+------------------------------------------------------+
| 방송 문구  [________________________________]         |
| 0 / 1000자                                            |
| 언어 [한국어 v]         보이스 [여성 A v]              |
| 파일 이름 [_____________]      [ 음성 만들기 ]         |
|                                                      |
|  -- 만든 뒤: 위 입력은 전부 잠기고 버튼도 비활성 --     |
|  +------------------------------------------------+  |
|  | pop2.mp3                               1.3초    |  |
|  | [ ▶ 재생바 ]                                    |  |
|  | 들어보고 저장하면 파일함에 등록됩니다.            |  |
|  |              [ 음성 저장하기 ]                   |  |
|  +------------------------------------------------+  |
+------------------------------------------------------+
```

- **[음성 만들기]는 파일 이름 입력란 옆에 둔다.** 하단 버튼 줄을 없앴으므로 만들기 동작이 입력 흐름의 끝에 바로 붙는다.
- **한 번 만들면 입력을 잠근다.** 문구·언어·보이스·파일 이름이 모두 비활성이 되고 [음성 만들기]도 비활성이 된다. 문구를 고쳤는데 아래 음원은 예전 것인 상태가 생기면 들은 것과 저장되는 것이 달라지기 때문이다. 다시 만들려면 닫고 새로 연다.
- **[음성 저장하기]를 눌러야 파일함에 남는다.** 서버는 합성하는 즉시 파일 행을 만들지만(별도 저장 단계가 없다), 저장 없이 닫으면 화면이 그 파일을 지운다(`DELETE /api/files/:id`). 들어보고 버린 음성이 파일함에 쌓이지 않게 하기 위해서다. 단, 기존 합성본을 재사용한 경우(`cached=true`)는 지우지 않는다 — 전부터 쓰던 파일을 이 화면이 지우면 안 된다.

**업로드 규격 확인 (2026-09-07, 문제점 31번)**: 올린 mp3 가 방송 규격(16kHz · mono · 설정 비트레이트)보다 음질이 낮으면 서버가 거절하고 그 사유를 그대로 보여준다. 규격보다 높으면 변환할지 팝업으로 묻는다 — 「이 파일은 44kHz 2ch 128kbps 입니다. 방송 규격(16kHz mono 24kbps)으로 변환해서 등록할까요? 변환하면 파일 안의 tag 정보는 모두 지워집니다.」 확인하면 같은 파일을 `?transcode=true` 로 다시 보내 변환 등록하고, 취소하면 그 파일만 건너뛴다(여러 개를 한 번에 올렸을 때 나머지는 계속 진행).

- 시각은 하나. 둘 원하면 규칙 둘. 모든 시각은 한국 시간.

## 9. OTA 관리 (super_admin)

```
+------------------------------------------------------+
| pkg 업로드: [IOT_RADIO.pkg] size=1.6MB sha256=...       |
| 방송 대상: (o)전체 ( )마을[..v] ( )개별[검색]              |

+------------------------------------------------------+
| job#5  대상10대  DOWNLOADING 3대/VERIFYING 1대/COMPLETED 5대/FAIL 1대 |
|   [상세]                                                |
+------------------------------------------------------+
```

2026-08-20부터 OTA_APPLY가 폐지되어 "적용 승인" 버튼은 없다 — 단말이 다운로드/검증(COMPLETED)까지 확인되면 관리자 개입 없이 곧바로 적용+재부팅까지 자동 진행한다. 화면은 진행 상태(주로 DOWNLOADING/VERIFYING/COMPLETED/FAIL 집계)를 보여주기만 하고, 최종 성공 여부는 재부팅 후 단말이 다시 접속했을 때의 STATUS 펌웨어 버전으로 판단해 job 목록에 반영한다.

OTA 진행 중인 단말은 3(단말관리)·4(방송제어) 화면에서 "OTA 중" 배지 표시 + 방송 버튼 비활성화.

## 10. 설정 (super_admin)

```
+------------------------------------------------------+
| status_interval_sec      [30    ]                       |
| live_stats_interval_sec  [10    ]                       |
| event_qos                (o)0  ( )1                     |
| [ 저장 (전체 단말에 즉시 적용) ]                            |
+------------------------------------------------------+
```

**세 구역으로 나눈다 (2026-09-03 두 구역, 09-06 오디오 추가 — 문제점 7·29·30번)**: 「단말 공통 CONFIG」(STATUS 주기 · LIVE_STATS 주기 · 이벤트 QoS — 저장하면 전 단말에 재발행)와 「방송 응답 시간」(라이브 준비 제한 · 라이브 종료 대기 · 파일방송 응답 대기 — 서버 안에서만 쓰여 재발행 없음)을 제목과 굵은 구분선으로 가른다. 한 목록에 섞어 두면 "저장하면 전 단말에 발행된다"는 안내가 응답 시간 항목에도 붙어 보인다. 저장 결과 문구도 사실대로 — CONFIG 가 바뀌었을 때만 "재발행되었습니다", 응답 시간만 바꿨으면 "단말 재발행은 없습니다". 응답 시간의 설명은 시작을 먼저, 종료를 뒤에 쓴다(문제점 8·9번). 파일방송 응답 대기는 시작(다 받고 검증 완료 → 재생 시작)과 중지 둘 다에 쓰는 값 하나다(기본 30초, 10~60 — 문제점 19번). 항목 순서는 방송 흐름대로 파일방송 응답 대기 → 라이브 준비 제한 → 라이브 종료 대기(문제점 12번).

세 번째 구역은 「오디오 품질」이다 — 라이브 스트림 속도와 MP3 파일 속도를 16 / 24kbps 중에 고른다(드롭다운, 기본 24). 표본율 16kHz · mono 는 통신 사양 고정이라 화면에 두지 않는다. 이것도 단말 재발행이 없으므로 저장 문구는 「서버 안에서만 쓰는 값이라 단말 재발행은 없습니다」로 묶는다. 적용 시점을 안내에 적는다 — 라이브는 다음 방송부터, MP3 는 이후에 올리거나 합성하는 파일부터이고 이미 파일함에 있는 파일은 그대로 둔다.

## 10a·11. 지역 관리 `/regions` (기관 관리자 이상, 2026-09-12 v2)

기관 관리(10a)와 마을·구역 관리(11)를 **탐색기 하나**로 합쳤다. VS Code 파일 탐색기의 손놀림 — 기관은 폴더, 마을은 파일.

```
+--------------------------------+----------------------------------------------+
| 지역        [📁+][📍+][∨][∧]    | 충청남도 › 금산군청                            |
| [이름으로 찾기            ]    | 📂 금산군청       [이름 바꾸기][+새 기관][+새 마을][삭제] |
| ∨ 📂 경기도          기관 2    | ┌하위기관┐┌ 마을 ┐┌ 단말 ┐┌온라인┐             |
|   > 📁 군포시        마을 1    | │  0    ││  3   ││  6   ││  4   │             |
|   ∨ 📂 안양시        기관 2    | └───────┘└──────┘└──────┘└──────┘             |
|     > 📁 만안구      기관 1    | 마을 3                                        |
|     > 📁 동안구                |  계곡마을  충남 금산군 계곡길 2  4471…01  0/2   |
| ∨ 📂 충청남도        기관 1    |  금산마을  —                   00000013  3/3   |
|   ∨ 📂 금산군청      마을 3    |  라라마을  강원 루루군 라라리 3  5199…01  1/1   |
|       📍 계곡마을        0/2   |                                              |
|       📍 [신규마을      ]  ←입력칸 (Enter 생성 · Esc 취소)                      |
|       📍 금산마을        3/3   |                                              |
| > 📁 기관 없음            1    |                                              |
| F2 이름 · Del 삭제 · ← → 접기 · 끌어서 옮기기 · 우클릭 메뉴                     |
+--------------------------------+----------------------------------------------+
```

- **만들기**: 마디를 고르고 [새 기관]/[새 마을] → 그 폴더 바로 아래 입력칸. 마을을 고른 채 누르면 그 마을의 폴더 안에. 아무것도 안 골랐으면 최고 관리자는 뿌리, 기관 관리자는 자기 기관. 뿌리 기관은 최고 관리자만.
- **이름 바꾸기** F2(또는 우클릭·패널 버튼) · **삭제** Delete(확인창, 빈 폴더만 — 하위·마을·계정이 남으면 버튼 비활성 + 이유 툴팁) · **↑↓←→ Enter** 이동/접기/펼치기 · **검색**(걸리는 마디만, 전부 펼침) · **모두 펼치기/접기**.
- **옮기기**: 끌어다 놓기 → 확인창. 순환·관할 밖·같은 자리는 놓을 자리로 표시되지 않는다. 기관 관리자의 자기 마디(「내 기관」 태그)는 못 옮기고 못 지운다. 기관을 뿌리로 올리는 것은 최고 관리자만(트리 아래 놓기 영역).
- **오른쪽 — 기관**: breadcrumb, 타일(하위 기관·마을·단말·온라인 = 아래 전부 합계, 바로 아래 수는 작게), 하위 기관 목록, 마을 표(누르면 그 마을로).
- **오른쪽 — 마을**: 타일(단말·온라인·구역·village_id), **위치·주소** 카드(주소 검색 → 도로명·지번·법정동코드·좌표 자동, 시/도·시/군/구·상세·위경도, 되돌리기/저장), **구역** 카드(추가·삭제), **단말** 표(MAC·별칭·상태·구역·마지막 접속, 단말 관리 링크). 주소는 마을에만 있다 — 지도에 찍히는 것은 마을이라서다.
- **기관 없음**: `organization_id` 가 null 인 마을 묶음. 최고 관리자만 본다. 기관 아래로 끌어다 놓으면 그 기관 관리자에게 보이기 시작한다.
- 옛 경로 `/organizations`·`/villages` 는 `/regions` 로 넘어간다.

## 12. 계정 관리 (시·군 이상)

```
+------------------------------------------------------------+
| 계정 목록                                      [+ 계정 추가]  |
| 김이장  village_admin  담당: OO리      2026-09-22 (15일)[수정]|
| 박이장  village_admin  담당: XX리,YY리  만료됨            [수정]|
| admin   super_admin    전체            무기한             [수정]|
+------------------------------------------------------------+
```

**계층 (2026-09-08, v2 09-12)**: 역할은 최고 · 기관 · 마을 셋이고 드롭다운에 내가 만들 수 있는 역할(기관 관리자 · 마을 관리자)만 나온다. 기관 관리자면 소속 기관을 트리 순서(들여쓰기)로 고른다 — 기관 관리자 본인의 마디는 목록에서 빠진다(같은 마디는 동료라 서버가 거절). 이장이면 담당 마을을 체크한다. 목록의 「범위」 열은 기관 이름 또는 마을 이름을 보인다.

**사용 기간 (2026-09-07, 문제점 26번)**: 계정을 추가·수정할 때 사용 기간을 고른다 — 1~30일(기본 15일) 또는 무기한. 기간이 끝나면 로그인이 막히고 정리 작업이 계정을 지운다. 목록에는 만료일과 남은 날짜를 같이 보이고, 3일 이하로 남았거나 이미 지난 계정은 눈에 띄게 표시한다. 수정 화면에서 저장하면 기간은 **오늘부터 다시 센다**(연장). 무기한은 상시 운영 계정용이며, 마지막 최고 관리자는 만료되어도 지우지 않고 로그인만 막는다.

게스트 계정의 기간 설정(문제점 27번)과 계정 삭제 시 파일함·이력·스케줄 처리(문제점 28번)는 21번 탭의 역할 사양(중간관리자·게스트, 마을 단위 파일함·이력·스케줄 분리)이 정해진 뒤에 붙인다. 지금은 계정을 지워도 파일과 이력은 남고 「올린 사람·실행자」만 비워진다(0014).
