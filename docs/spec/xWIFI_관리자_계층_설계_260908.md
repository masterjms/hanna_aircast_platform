# xWIFI 관리자 계층 설계 (2026-09-08 · v2 2026-09-12)

관리자 권한을 조직 트리로 나눈다. 이 문서는 그 결정과 데이터 모델, 권한 규칙의 정본이다. 문제점 리스트 21번 탭의 역할표(최고·중간·일반·게스트)를 **대체**한다 — 게스트 역할은 두지 않는다.

**v2 (2026-09-12) 에서 바뀐 것** — 요구사항 재확인 결과:

| | v1 (09-08) | v2 (09-12) |
|---|---|---|
| 트리 깊이 | 시·도 > 시·군 두 단 고정 | **제한 없음.** 2단이든 5단이든 사용자가 정한다 |
| 기관 역할 | `sido_admin`(2) · `sigungu_admin`(1) | **`org_admin` 하나.** 기관 관리자끼리의 위아래는 트리 위치가 정한다 |
| 기관의 속성 | 이름 · 수준 · 상위 · 관할 코드(공식/운영 구분) | **이름 · 상위뿐.** 공식/운영 개념과 주소 제안을 없앴다 |
| 주소 | 기관에 관할 코드, 마을에 주소 | **마을에만.** 지도에 찍히는 것은 마을이라 마을만 정확하면 된다 |
| 기관 CRUD | 최고 관리자만 | 기관 관리자도 **자기 아래**에서 |
| 화면 | 기관 관리 + 마을 관리 두 표 | **지역 관리 탐색기 하나** — VS Code 파일 탐색기 방식 |

관련: [운영서버 구성 개요](xWIFI_운영서버_구성_개요_260813.md) · [DB 스키마](xWIFI_DB_스키마_260815.md) · [API 설계](xWIFI_API_설계_260815.md) · [화면 설계](xWIFI_화면_설계_260815.md) · [지도·위치 설계](xWIFI_지도_위치_설계_260831.md)

## 1. 핵심 결정

**권한은 조직 트리를 따른다. 주소는 트리의 입력값이 아니다.**

처음에는 법정동코드 앞자리(시도 2자리 · 시군구 5자리)로 관할을 자동 결정하는 안을 검토했다. 마을을 만들 때 주소만 넣으면 어느 군청·도청 소속인지 저절로 정해지므로 사람이 입력할 것이 없다는 장점이 있었다. 그러나 다음 시나리오에서 깨진다.

> 새로 영입한 라라마을은 주소상 루루군(강원)에 있다. 그런데 루루군청이 아니라 기존 고객인 금산군청(충남)이 관리하기로 구두 약속했다.

주소로 관할을 정하면 이 마을은 금산군청 계정에 영영 보이지 않는다. 보이게 하려면 주소를 거짓으로 넣어야 하고, 그러면 지도 폴리곤과 MQTT 토큰이 거짓이 된다. 지방 소도시에서 이런 위탁·겸임은 예외가 아니라 흔한 일이다.

그래서 **지리(주소)** 와 **관할(누가 관리하나)** 을 분리한다.

| | 지리 | 관할 |
|---|---|---|
| 저장 | `villages.b_code` (마을에만) | `villages.organization_id` |
| 정하는 것 | 주소 검색 | 사람 — 탐색기에서 마을을 어느 마디 아래 두느냐 |
| 쓰는 곳 | 지도 폴리곤·마커, MQTT 토큰 | 권한 범위 |
| 바뀌는 때 | 행정구역 개편 | 위탁·이관 (끌어다 놓기) |

v2 에서 **기관은 주소를 갖지 않는다.** 「경기도 > 안양시 > 만안구」처럼 행정구역 이름을 써도 되고 「A권역 > 북부팀」처럼 자체 묶음을 써도 된다 — 시스템은 둘을 구분하지 않는다(공식/운영 구분 없음). 지도에 찍히는 것은 마을이므로 마을의 주소만 정확하면 된다.

## 2. 역할

| `role` | 표시 | 범위 근거 | 계층 |
|---|---|---|---:|
| `super_admin` | 최고 관리자 | 전체 | 2 |
| `org_admin` | 기관 관리자 | 소속 기관과 **그 아래 전부**(부분 트리) | 1 |
| `village_admin` | 마을 관리자 (이장) | `user_villages` (지금과 같음) | 0 |

기관 관리자끼리는 역할 이름이 아니라 **트리 위치**가 위아래를 정한다. 도청 마디의 관리자는 그 아래 군청 마디의 관리자를 관리하고, 같은 마디의 관리자끼리는 동료라 서로 만지지 못한다. 그래서 「시·도 관리자」「시·군 관리자」라는 역할 이름이 필요 없어졌고, 계층이 5단이 되어도 역할을 늘리지 않는다.

계층 숫자는 "누가 누구를 관리하나"의 큰 순서다. 최고 관리자는 최고 관리자를 만들지 않는다(배포 때 만든다).

## 3. 데이터 모델

```
organizations
  id, name, parent_id → organizations (NULL = 뿌리), created_at

villages.organization_id  → organizations  (NULL 허용, ON DELETE RESTRICT)
users.organization_id     → organizations  (NULL 허용, ON DELETE RESTRICT)  -- org_admin 만
user_villages             → 그대로 (village_admin 전용)
```

```
 경기도
 ├─ 안양시
 │   ├─ 만안구
 │   │   └─ 안양권역 ── 안양1동마을
 │   └─ 동안구
 └─ 군포시 ── 산본마을
 충청남도
 └─ 금산군청 ── 금산마을, 계곡마을, 라라마을(주소는 강원)
```

규칙:

- 깊이 제한이 없다. 마디는 이름과 부모뿐이다. 마을은 어느 마디에나 붙는다.
- 순환은 API 가 막는다(`ORG_CYCLE`) — 자기 자신이나 자기 후손을 부모로 둘 수 없다. 트리 판정은 `app/core/orgtree.py` 한 곳이 하며, 기관 전체를 질의 한 번으로 읽어 메모리에서 탄다(기관은 많아야 수백 개; 질의 수가 깊이와 무관).
- `villages.organization_id` 가 NULL 인 마을(주소 없는 시험 마을 등)은 최고 관리자만 본다. 탐색기에서는 「기관 없음」 묶음이다.
- 기관은 하위 기관·소속 마을·계정이 하나라도 있으면 지울 수 없다(`ORGANIZATION_IN_USE`). 빈 폴더만 지운다. 연쇄 삭제는 두지 않는다 — 마을에는 단말·이력·스케줄이 매달려 있다.
- `users.organization_id` 는 `org_admin` 에만 있다. `village_admin` 은 `user_villages`, `super_admin` 은 둘 다 없다.

## 4. 범위 산출

로그인·요청마다 `VillageScope`(마을 id 집합)를 만든다. **이 아래 계층은 바뀌지 않는다** — 조회 필터, 겹침 검사, MQTT 발행 직전 2중 방어가 전부 이 집합만 본다.

| 역할 | 마을 집합 |
|---|---|
| `super_admin` | 전체 (`all_villages=True`) |
| `org_admin` | `organization_id IN subtree(내 기관)` — 자기 + 모든 후손 마디 |
| `village_admin` | `user_villages` |

기관이 NULL 인 기관 관리자는 빈 범위다. 담당 마을 없는 마을 관리자와 같은 상태이고 화면 경고도 같다.

`org_ids_under(user)` = 내 기관의 부분 트리. 마을·기관·계정 관리 API 는 전부 이 집합으로 "내 관할인가"를 판정한다.

## 5. 권한 매트릭스

원칙: **운영은 관할 전체에, 구조 변경은 출발지와 도착지가 모두 내 관할일 때만, 계정은 나보다 아래 마디만.**

| | 이장 | 기관 관리자 | 최고 |
|---|---|---|---|
| 단말 상태·이상단말·지도·이력 조회 | 내 마을 | 관할 | 전체 |
| 방송 시작·중지·스케줄·파일함 | 내 마을 | 관할 | 전체 |
| 전체(`all`) 대상 방송 | ✗ | ✗ | ○ |
| 구역 추가·수정·삭제 | 내 마을 | 관할 | 전체 |
| 단말 별칭·위치 수정 | 내 마을 | 관할 | 전체 |
| 단말 마을 이동 | ✗ | 관할 안에서 | 전체 |
| 마을 추가·이름·주소·삭제 | ✗ | 관할 안에서 | 전체 |
| 마을 옮기기(관리 기관 변경) | ✗ | 관할 안의 마디 사이 | 전체 |
| 기관 추가·이름 바꾸기·삭제 | ✗ | 자기 마디 **아래**에서 | 전체 (뿌리 포함) |
| 기관 옮기기 | ✗ | 관할 안의 마디 사이 (자기 마디는 못 옮김) | 전체 |
| 계정 생성·수정·기간·삭제 | ✗ | 아래 마디의 기관 관리자, 관할 이장 | 전체 |
| 신규 단말 등록 (MQTT 계정 발급·재발급) | ✗ | ✗ | ○ |
| 미배정 단말 조회·배정 | ✗ | ✗ | ○ |
| 단말 삭제 · OTA · CONFIG 설정 | ✗ | ✗ | ○ |

「계정은 아래 마디 전부」다 — 도청 관리자가 이장 계정까지 만들 수 있다. 같은 마디의 기관 관리자는 만들 수 없다(`TIER_TOO_LOW`): 만들 수 있게 두면 관할이 옆으로 샌다.

기관 CRUD 를 기관 관리자에게 연 이유: 마디가 자유로운 묶음이 되었으므로(공식 행정구역이 아니어도 됨) 군청 관리자가 자기 아래에 「북부권역」을 만드는 것은 자기 살림이다. 뿌리 마디만 최고 관리자가 만든다.

`all` 대상 방송을 최고 관리자에 묶는 이유: 기관 관리자가 관할 전체에 방송하려면 스케줄의 `organization` 대상이나 `village` 대상에 관할 마을 전부를 넣으면 된다. `all` 은 "시스템의 모든 단말"이고 그건 개발자만 눌러야 한다.

## 6. 구조 변경 규칙

### 6.1 단말의 마을 이동

정당한 동작이다. 단말은 실제로 옮겨 달리고 설치 때 마을을 잘못 고르기도 한다.

- 출발 마을과 도착 마을이 **모두** 관할 안이어야 한다. 관할을 넘는 이동은 두 관할을 다 가진 위 마디의 관리자나 최고 관리자가 한다.
- 화면은 확인 대화상자다(단말 관리). 마을이 바뀌면 단말의 CONFIG(village_id 토큰)가 다시 내려가고 ACL 이 재생성된다.

### 6.2 마을·기관 옮기기 (탐색기 드래그)

정당한 동작이다. 라라마을이 그 예다.

- 출발(지금 자리)과 도착(새 부모)이 모두 관할 안이어야 한다. 기관 관리자는 결과적으로 자기 마디를 못 옮긴다 — 관할 안의 도착지는 전부 자기 아래라 순환이다.
- 탐색기에서 끌어다 놓되 **놓을 때 한 번 묻는다.** 손가락이 미끄러져 옆 기관에 떨어지는 일에 확인 없이 일어나면 안 된다. 기관을 옮기면 그 아래 전부의 관할이 한 번에 바뀐다.
- 마을을 옮겨도 `b_code`·`village_code`·폴리곤·단말 CONFIG 는 **아무것도 바뀌지 않는다.** 단말은 누가 관리하는지 모르고 알 필요도 없다.

### 6.3 주소 수정은 관할 변경이 아니다

마을 주소를 잘못 넣은 것을 고치는 것은 `b_code` 수정이다. 관할은 그대로다. 지도 설계 §1.3 대로 `village_code` 도 고정이다. 주소를 처음 넣어 옛 8자리 토큰이 12자리로 바뀌는 경우만 단말 CONFIG 가 다시 내려간다.

## 7. 시나리오: 라라마을

1. **영입.** 최고 관리자가 탐색기에서 「금산군청」을 고르고 [새 마을] → 「라라마을」. 마을 패널에서 주소를 넣으면 `b_code` 는 루루군 코드로 정확히 들어가고 폴리곤도 실제 위치에 그려진다. 루루군청 마디는 만들지 않는다.
2. **다음 날 금산군청 직원 로그인.** 범위가 `subtree(금산군청)` 으로 풀리므로 라라마을이 바로 보인다.
3. **1년 뒤 루루군청이 직접 하기로 함.** 최고 관리자가 「강원도」 아래에 「루루군청」을 만들고 라라마을을 끌어다 놓는다. 확인 한 번으로 금산군청 전 계정에서 사라지고 루루군청 전 계정에 나타난다. 단말은 아무것도 모른다.
4. **루루군청 계정을 마을보다 먼저 만들면** 빈 범위로 로그인된다.

결과 하나를 명시한다: 라라마을은 **충청남도 관리자에게 보이고 강원도 관리자에게는 보이지 않는다.** 관할은 조직 트리를 따르지 지리를 따르지 않는다.

## 8. 진행 중 방송의 가시성

**대상 단말의 소속 마을 중 하나라도 내 범위면 보이고, 보이면 중지할 수 있다.** (v1 과 같다.)

| `target_scope` | 판정 |
|---|---|
| `village` | 대상 마을 중 하나라도 범위 안 |
| `zone` | 구역의 마을이 범위 안 |
| `device` | 대상 단말의 마을 중 하나라도 범위 안 |
| `all` | 범위가 비어 있지 않으면 보인다 |

## 9. 화면 — 지역 관리 탐색기

기관 관리·마을 관리 두 화면을 `/regions` 「지역 관리」 하나로 합쳤다. 사람들이 가장 많이 써 본 트리 조작인 **VS Code 파일 탐색기**의 손놀림을 그대로 쓴다.

- **왼쪽 트리**: 기관 = 폴더, 마을 = 파일. 들여쓰기로 깊이를 보이고, 폴더 옆에 「마을 n · 기관 n」, 마을 옆에 「온라인/전체」 대수.
- **만들기**: 마디를 고르고 [새 기관] 또는 [새 마을] → 그 폴더 바로 아래에 입력칸이 열리고 Enter 로 만든다(Esc 취소). 마을을 고른 채 누르면 그 마을의 폴더 안에 생긴다. 아무것도 안 골랐으면 최고 관리자는 뿌리, 기관 관리자는 자기 기관.
- **이름 바꾸기** F2 · **삭제** Delete(확인창; 빈 폴더만) · **↑↓←→** 이동/접기/펼치기 · **우클릭 메뉴** · **검색**(걸리는 마디만 남기고 전부 펼침) · **모두 펼치기/접기**.
- **옮기기**: 끌어다 놓기. **브라우저의 HTML5 드래그(dragstart/drop)를 쓰지 않고** 포인터 누름·이동·뗌으로 직접 끈다 — HTML5 드래그는 OS 드래그 기능에 넘겨져 처리되는데, 운영 PC 에서 브라우저가 드래그를 끝맺지 못해 페이지가 갇히는 일이 반복됐고 개발 PC 에선 재현되지 않았다(2026-09-12). 6px 이상 움직여야 끌기이고, 끌리는 이름표가 커서를 따라간다. 놓을 때 확인은 앱 모달(§6.2). 순환·관할 밖·마을 행은 놓을 자리로 표시되지 않는다. 뿌리로 올리는 것은 최고 관리자만(트리 아래 놓기 영역 또는 빈 자리). Esc 로 취소. 터치에서는 세로 스크롤만 되고 끌기는 마우스로 한다.
- **오른쪽 패널**: 기관이면 breadcrumb · 타일(하위 기관 · 마을 · 단말 · 온라인, 아래 전부 합계) · 하위 기관·마을 목록. 마을이면 타일(단말 · 온라인 · 구역 · village_id) · **위치·주소**(주소 검색 → 도로명·지번·법정동코드·좌표 자동, 저장 버튼) · 구역 · 소속 단말 표.
- **권한 표시**: 기관 관리자에게 자기 마디는 「내 기관」 태그가 붙고 옮기기·삭제가 비활성이다. 뿌리 기관 추가 버튼은 최고 관리자만. 서버가 거절할 삭제(하위·마을·계정이 남음)는 누르기 전에 비활성 + 이유 툴팁.
- **계정 관리**: 역할 드롭다운은 기관 관리자 · 마을 관리자. 기관 관리자면 소속 기관을 트리 순서(들여쓰기)로 고르되 기관 관리자 본인의 마디는 목록에서 빠진다. 이장이면 담당 마을 체크.
- **스케줄 위자드**: 「어디에」 트리가 같은 모듈(`lib/orgtree.ts`)로 깊이 무관하게 그려진다. 기관 마디 = 관할 전체(아래 전부).

## 10. 마이그레이션

- **0015** (v1): `organizations` 생성, `villages.organization_id`, `users.organization_id`, 역할 두 개 추가.
- **0018** (v2): `organizations.level`·`jurisdiction_code` 삭제, `users.role` 의 `sido_admin`·`sigungu_admin` → `org_admin`. 기존 계정의 소속·범위는 그대로다(부분 트리는 v1 의 "자기 + 바로 아래"를 포함한다). downgrade 는 2단 트리로만 되돌릴 수 있다 — 3단 이상으로 쓴 뒤 내리면 옛 코드의 가정이 깨지므로 내리기 전에 사람이 정리한다.

## 11. 이 방식의 단점 (알고 가는 것)

- **역할 이름이 계층을 말해 주지 않는다.** 계정 목록의 「기관 관리자」만 보고는 도청인지 군청인지 모른다 — 소속 기관 열(경로)을 같이 봐야 한다.
- **트리 모양이 고객마다 다르다.** 한 고객은 3단, 다른 고객은 5단으로 쓴다. 이름도 자유 텍스트라 「안양시」가 두 곳에 있을 수 있다. 시스템이 행정구역과 대조하지 않는다.
- **주소로 마을의 기관을 제안하지 않는다.** 마을을 어느 마디에 둘지는 사람이 정한다(탐색기에서 고른 자리). 위탁 마을이 흔해 제안이 틀리는 일이 많았으므로 잃는 것은 크지 않다.
- **깊은 트리는 화면이 길어진다.** breadcrumb 과 스케줄 위자드의 트리가 5단이면 길다. 탐색기의 접기·검색으로 다룬다.
- **빈 폴더만 지운다.** 큰 부분 트리를 없애려면 안의 것을 먼저 옮겨야 한다. VS Code 처럼 폴더째 지우는 것은 마을의 단말·이력·스케줄 때문에 두지 않았다.
- **기관을 옮기면 관할이 한 번에 크게 바뀐다.** 그래서 확인창을 두고, 기관 관리자는 자기 마디를 못 옮긴다.
- **인라인 입력은 키보드 중심이다.** 태블릿에서는 우클릭 메뉴 대신 길게 누르기가 없다 — 오른쪽 패널의 버튼(+ 새 기관 · + 새 마을 · 이름 바꾸기 · 삭제)이 같은 일을 한다.
- **부분 트리를 요청마다 계산한다.** 기관 전체를 한 번 읽어 메모리에서 탄다. 기관이 수만 개가 되면 캐시가 필요하다 — 지금 규모(수백)에서는 질의 1회로 끝난다.

## 12. 이번에 넣지 않는 것

- 조회 전용 지리 범위 ("자기 땅의 마을은 다 본다") — 관할과 별개 개념
- 마을별 비용 조회 API
- 「사용 여부」 스위치 — 껐을 때 방송·스케줄·계정·지도에서 무엇이 멈추는지 정책이 먼저다
- 계정별 파일함 분리 (문제점 28번)
- 트리 순서 수동 정렬 — 이름순 고정
