# 단말별 브로커 계정 사양

작성: 2026-08-27. 갱신: 2026-08-30.

**username = 단말 MAC. password는 8자, 문자 집합 확정.** 브로커 등록 방법은 서버 재량이다.

### 개정 이력

| 날짜 | 바뀐 것 |
|---|---|
| 08-30 | **계정은 한 번 발행하면 안 바꾼다.** 도난 단말은 삭제로 막는다 (§4) |
| 08-30 | password **8자 확정.** 문자 집합과 **왜 8자인지** (§1) |
| 08-30 | **이행 기간 삭제** — 현장 단말이 없어 일괄로 바꾼다 |
| 08-30 | **회전용 MQTT push 삭제** — 교체는 시리얼로 한다 (§4) |
| 08-30 | 브로커 등록 방식을 **서버 재량**으로 (§5) |
| 08-29 | username = 단말 MAC 확정 |
| 08-27 | 최초 작성 |

배경과 왜 이 방식인지는 `spec/SECURITY_HARDENING_PLAN_2026-08-27.md` §1.2에 있다. 여기는 **무엇을 어떻게 만드는가**만 적는다.

---

## 1. 무엇을 바꾸나

```text
지금:  전 단말이 같은 계정 하나
       → 하나 뚫리면 전 마을이 열린다
       → ACL이 client_id(%c, 클라이언트가 주장하는 값)로 판정한다

바꾼 뒤: 단말마다 다른 계정
       → 뚫려도 그 단말 하나
       → ACL이 username(%u, 비밀번호로 증명된 값)으로 판정한다
```

### 계정 형태

| | 값 |
|---|---|
| **username** | 콜론 없는 소문자 MAC. 지금 `client_id`와 **같은 값** |
| **password** | MAC별 랜덤. **서버가 발행하고 DB에 보관** |

username은 비밀이 아니다 — 바코드·화면·QR에 이미 MAC이 있다. **비밀은 password뿐이다.**

### password 규칙 (2026-08-30 확정)

```text
길이     8자
문자     a-z  A-Z  0-9  # $ % ^ & * - _ + = ? . ~
```

**조합은 서버가 정한다.** 단말은 검사하지 않는다.

#### 왜 8자인가 — 단말 화면에서 손으로 칠 수 있어야 한다

예외적으로 **단말 UI에서 비밀번호를 직접 입력**하는 경우가 있다. **터치가 없어 버튼으로 글자를 하나씩 골라야 하므로** 길면 실용적이지 않다.

위 문자는 **단말 키보드에 전부 있다.** 서버가 이 집합 밖의 문자를 쓰면 **손으로 입력할 방법이 없어진다.**

#### `@`는 쓰지 않는다

시리얼 프로토콜이 `@`로 명령을 구분하고, 요청의 끝을 `@END`로 판정한다. 비밀번호 안에 `@END`가 들어가면 **전송이 그 자리에서 잘린다.** 확률은 낮지만 라인에서 원인을 찾기 어려운 실패다.

단말 키보드에는 `@`와 `!`가 있지만 **서버는 쓰지 않는다.**

단말이 받아들이는 한계는 최대 127자, ASCII 표시 가능 문자(`0x20`~`0x7E`)다. **8자는 그 안에 넉넉히 든다.**

## 2. 서버가 할 일

### 2.1 계정 발행

| # | 항목 | 비고 |
|---|---|---|
| 1 | 단말 등록 시 **MAC별 랜덤 password 생성** | **8자.** 문자 집합은 §1 |
| 2 | DB에 보관 | MAC 키 테이블(`SERVER_DEVICE_REGISTRY_2026-08-27.md` §3)에 열 추가 |
| 3 | **브로커 password 파일에 등록** | `mosquitto_passwd` 등. 등록 후 브로커가 다시 읽게 한다 |
| 4 | 등록 화면에 **계정을 표시** | 생산에서 시리얼로 넣어야 한다 |

**3번이 유일하게 새로운 운영 작업이다.** 나머지는 지금 만들고 있는 등록 흐름 안에 들어간다.

수백 대 규모면 `mosquitto_passwd` + 설정 리로드로 충분하다. 규모가 커지면 DB 연동 인증 플러그인을 검토한다. **mosquitto는 password를 해시로 저장하므로 브로커가 뚫려도 평문이 나오지 않는다.**

### 2.2 ACL 변경

**규칙 구조는 그대로다. 치환 문자만 바뀐다.**

```text
지금:  ... %c ...     (client_id — 클라이언트가 주장하는 값)
바꾼 뒤: ... %u ...    (username — 비밀번호로 증명된 값)
```

topic 목록은 `SERVER_COMM_MQTT_ICECAST_HTTP_SPEC_2026-08-14.md` §2.1 그대로다.

**`iotradio/village/<village_id>/cmd`는 여전히 예외다.** MAC이 아니라 서버가 배정한 값이 들어가므로 `%u`로도 안 잡힌다. 별도 규칙이 필요하다.

## 3. 단말에 넣는 경로 — 시리얼뿐이다

**계정이 없는 단말은 브로커에 붙지 못한다.** 그래서 계정은 반드시 물리적으로 넣어야 한다. `@MQTTID`/`@MQTTPW`는 이미 동작한다.

```text
> @MQTTID=58e6c5f2cc74
> @MQTTPW=<서버가 발행한 값>
> @END
@RESULT=OK
@MQTTID=58e6c5f2cc74
@MQTTPW=SET
@END
```

생산 흐름(`DEVICE_REGISTRATION_FLOW_SPEC_2026-08-29.md` §B2)에 한 단계가 붙는다.

```text
1. 바코드/QR 스캔      → 서버에 MAC 등록
2. 서버가 계정 응답     → username=MAC, password=<8자 랜덤>   ← 새로 생기는 것
3. 시리얼로 투입       → @MQTTID / @MQTTPW / @SSID ...
```

**2번만 새로 생긴다.**

## 4. 계정은 한 번 발행하면 그대로 간다

**발행한 계정을 나중에 바꾸지 않는다.** username은 MAC이라 애초에 안 바뀌고, password도 그 단말이 폐기될 때까지 같은 값을 쓴다.

### 4.1 왜 바꿀 일이 없나

**단말별 랜덤이라 한 대가 유출돼도 그 대만이다.** 그리고 그 한 대를 막는 방법은 비밀번호 교체가 아니다.

| 상황 | 조치 |
|---|---|
| 단말 도난·분실·회수 실패 | **그 MAC의 계정을 브로커에서 지운다** — 흐름 문서 §D3 「삭제」 |
| 단말 고장 → 교체 | **새 MAC에 새 계정.** 마을·주소·이름만 옮긴다 — §D2 |
| 마을·주소·이름이 바뀜 | **서버 DB만 고친다.** 계정과 무관하다 |

**비밀번호를 바꿔서 막는 것은 성립하지 않는다.** 바꾼 값을 그 단말에 넣으려면 케이블이 필요한데, 막아야 할 단말은 손에 없다.

### 4.2 [계정 재발행]은 라인 기능이다

**케이블이 꽂힌 상태에서만 쓴다.** 라인에서 재작업할 때 계정을 새로 받는 경우이고, 발행받은 값을 **그 자리에서 시리얼로 넣는다.**

| # | 서버가 하는 일 |
|---|---|
| 1 | 새 password 8자 발행 |
| 2 | DB 갱신 **+ 브로커 갱신** — 둘은 한 묶음이다(`SERVER_DEVICE_REGISTRY_2026-08-27.md` §3.6) |
| 3 | 등록 화면에 표시 → 시리얼로 투입 |

**재등록의 기본은 재사용이다.** 재작업이 흔하고 계정을 바꿀 이유가 없기 때문이다(흐름 문서 §7).

> **현장에 나가 있는 단말은 대상이 아니다.** 그쪽 계정을 바꿔야 하는 상황이 생기면 **별도 사양이 필요하다** — 지금은 그런 상황을 두지 않는다.

**MQTT로 밀어 넣는 경로는 만들지 않는다.**

## 6. 정해진 것

**확정된 것**

| 항목 | 결정 |
|---|---|
| 단말별 계정 | **간다.** username = 콜론 없는 소문자 MAC |
| 초기 투입 | 시리얼(`@MQTTID`/`@MQTTPW`). 생산 라인에서 |
| password | **8자.** `a-z A-Z 0-9 # $ % ^ & * - _ + = ? . ~` (§1) |
| 계정 교체 | **하지 않는다.** [계정 재발행]은 라인 기능이다(§4) |
| 이행 | **일괄로 바꾼다.** 공유 계정을 남겨 두지 않는다 |

**서버 재량**

| 항목 | |
|---|---|
| password 조합 방식 | 위 규칙만 지키면 된다 |
| 브로커 계정 등록 방식 | `mosquitto_passwd`든 인증 플러그인이든 **서버가 편한 대로** |

**서버 재량은 §6이다.** 다른 항목은 정해졌다.
