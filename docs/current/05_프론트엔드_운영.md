# xWIFI 프론트엔드와 운영 화면

기준일: 2026-09-06

구현: React 18, TypeScript, Vite

주 사용자: 마을 이장, 군청·지자체 관리자

관련 문서: [백엔드 API](03_백엔드_API.md) · [단말 연동](02_단말_연동_사양.md)

## 1. 화면 설계 원칙

사용자는 전문 시스템 운영자가 아니므로 화면은 기술 구조보다 **지금 무엇이 정상인지, 어디에 방송되는지, 다음에 무엇을 눌러야 하는지**를 먼저 보여줘야 한다.

- 한 화면의 주 작업은 하나로 제한한다.
- 방송 시작 전 대상과 온라인 대수를 문장으로 다시 확인시킨다.
- 색상만으로 상태를 구분하지 않고 상태명과 원인을 함께 쓴다.
- MAC, `job_id`, CONFIG version은 진단에 필요할 때 보조 정보로만 노출한다.
- 실패 메시지는 “무엇이 실패했는가 + 사용자가 할 다음 행동”을 포함한다.
- 삭제, credential 재발급, 전체 방송은 영향 범위를 확인한 뒤 실행한다.
- 표의 행과 버튼은 마우스 조작이 서툰 사용자도 누를 수 있는 충분한 크기를 유지한다.
- 전문 용어는 화면에서 풀어 쓰되, 운영자가 지원팀에 전달할 수 있도록 code를 상세 영역에 남긴다.

현재 UI는 어두운 테마와 왼쪽 고정 사이드바를 사용한다. 향후 시각 개편을 하더라도 아래 기능 흐름과 권한·상태 의미는 유지해야 한다.

## 2. 공통 레이아웃과 권한

로그인 후 화면은 사이드바, 상단 담당 범위, 본문으로 구성된다.

**화면에 맞추기(2026-09-21).** 페이지 전체는 스크롤하지 않는다. 제목·필터·버튼은 늘 제자리에 있고, 길어질 수 있는 것(표·기관 트리·목록)만 제 칸 안에서 돈다. 행이 적으면 표는 제 크기대로만 그린다. `.main` 의 세로 스크롤은 창이 아주 낮을 때의 안전망으로만 남긴다.

| 너비 | 배치 |
|---|---|
| 1180px 이상 (PC) | 왼쪽 메뉴 + 본문. 창이 낮으면(800px 이하) 메뉴 여백만 줄인다 |
| 901~1179px (태블릿 가로·좁은 창) | 왼쪽 메뉴를 접고 **하단 탭바**로 바꿔 본문에 자리를 준다. 본문은 PC 와 같은 「화면에 맞추기」 |
| 900px 이하 (폰·태블릿 세로) | 하단 탭바 + 본문이 위아래로 흐른다(스크롤 허용). 표는 글자를 꺾지 않고 표 상자 안에서 옆으로 민다. 마을 현황은 요약 → 지도 순으로 쌓는다 |

하단 탭바(`MobileNav`)의 항목·권한 규칙은 왼쪽 메뉴와 같고 끝에 로그아웃이 붙는다. 설정 화면은 1280px 이상에서 묶음을 두 단으로 펼친다.

| 역할 | 보이는 공통 기능 | 추가 기능 |
|---|---|---|
| `village_admin` | 대시보드, 단말 관리, 방송 제어, 파일함, 이력, 스케줄 | 담당 마을만 조회·제어, 자기 마을 구역 관리 |
| `org_admin` | 모든 공통 기능 | 지역 관리(기관·마을·구역 — 소속 기관 아래에서), 계정 관리(아래 마디의 기관 관리자, 관할 이장), 단말 마을 이동 — 관할 안에서 |
| `super_admin` | 모든 공통 기능 | 비용, OTA, 설정, 뿌리 기관·기관 없는 마을, 미배정 단말, 신규 단말 등록·삭제, 전체 방송 |

메뉴마다 최소 계층이 있다(`lib/roles.ts`). 프론트는 계층에 못 미치는 메뉴를 숨기고 route guard(`RequireRole`)로 직접 접근도 홈으로 돌린다. 이것은 편의 기능일 뿐 최종 권한 검사는 항상 백엔드가 수행한다. [관리자 계층 설계](../spec/xWIFI_관리자_계층_설계_260908.md).

상단 담당 범위에는 전체/담당 마을 수와 단말 수를 표시한다. 로그인 직후 받은 사용자 정보는 `/api/auth/me`로 복구한다.

현재 JWT는 `localStorage`에 저장한다. XSS 영향이 큰 방송 제어 시스템이므로 운영 보안 검토에서 CSP 강화와 `httpOnly`, `Secure`, `SameSite` 쿠키 전환을 함께 검토한다.

## 4. 갱신과 상태 표시

- 일반 화면 polling 기본: 5초
- 진행 중 방송이 있는 대시보드: 2초
- 방송 제어 진행 목록: 2초
- 단말 목록: 5초
- 마을·구역 같은 기준정보: 화면 진입 시 조회하고 저장 뒤 명시적으로 다시 읽음
- 같은 요청이 아직 진행 중이면 중복 polling을 만들지 않는다.

온라인 판정은 화면에서 추측하지 않고 API의 `online`과 요약 count를 사용한다.

| 상태 | 표시 의미 |
|---|---|
| 온라인 | 최근 5분 이내 STATUS 수신, LWT OFFLINE 아님 |
| 오프라인 | LWT 수신 또는 5분 이상 무응답 |
| 미배정 | 마을이 지정되지 않은 단말; `super_admin`만 관리 |
| 방송 준비 중 | LIVE_START 후 대상의 LIVE_READY 대기 |
| 송출 중 | 실시간 source와 방송 세션 진행 |
| 전송 중 | FILE_RESULT를 기다리는 파일 다운로드·검증 구간 |
| 재생 중 | FILE_RESULT 성공 후 음원 길이에 따른 재생 구간 |
| 중지 중 | STOP 발행 후 단말 종료 결과 대기 |
| 재접속 중·무음 | 단말 `live=RECONNECTING`; 방송 session은 살아 있으나 스피커 무음 |

## 5. 대시보드 `/`

목적은 로그인 직후 전체 이상 여부를 한눈에 판단하는 것이다.

왼쪽:

- 온라인 대수
- 오프라인 대수
- 진행 중 방송 건수
- `super_admin`에게 미배정 대수
- **기관 > 마을 > 단말** 계층 목록(향후검토 6번, 2026-09-21). 기관은 접힌 요약(온라인/전체, 오프라인·무음 대수)으로 시작하고 펼치면 하위 기관·마을, 마을을 펼치면 단말이다. 아래 단말이 오프라인이면 모든 상위 요약에 「오프라인 n」이 뜬다. 단말 없는 가지는 뺀다. 지도에서 핀을 누르면 그 단말이 든 가지가 저절로 펼쳐진다. 기관이 없는 이장 계정은 예전처럼 마을 목록
- 이상 단말 최대 20대: 별칭, 마을, 원인, 마지막 통신

오른쪽:

- 카카오 지도
- 마을 경계
- 단말 marker
- marker와 목록 선택·hover 연동
- 좌표가 없는 단말 목록

marker 상태:

| 상태 | 표현 |
|---|---|
| 정상 온라인 | 초록 |
| Icecast 재접속·무음 | 주황 + 문구 |
| 오프라인 | 빨강 |
| 단말 자체 좌표가 없어 상위 좌표 사용 | 반투명 + “위치 미입력” |
| 미배정 | 별도 상태 표기 |

멀리서 볼 때는 level 5부터 가까운 marker를 cluster 숫자로 묶는다. 단말을 선택하면 건물·골목이 보이는 level 3까지 확대하고 중앙으로 이동한다. 마을 경계가 있으면 지도 아래에 행정안전부 주소정보제공 출처를 표시한다.

지도 JavaScript key가 없거나 SDK가 실패해도 왼쪽 현황은 사용할 수 있어야 한다.

**지도 크기(향후검토 13번, 2026-09-21).** 지도 오른쪽 위의 [작게 35% · 보통 50% · 크게 65%] 버튼, 또는 목록과 지도 사이 손잡이를 끌어 25~75% 사이로 바꾼다(손잡이에 초점을 두고 ←→로 5%씩). 값은 그 브라우저에 기억된다. 기본은 50% — 예전 고정 60%가 크다는 지적이었다.

## 6. 단말 관리 `/devices`

### 6.1 목록

필터:

- 마을
- 상태: 전체·온라인·오프라인·미배정
- label 또는 MAC 검색

행의 핵심 정보:

- 별칭과 MAC
- 마을·구역
- 온라인과 최근 통신
- RSSI, IP, 동작 state, live 상태
- P4/C6 등록 정보와 현재 firmware
- CONFIG version
- MQTT credential 발행 여부

상세에서 `last_status` 원본을 확인할 수 있다. `has_credential=false`는 단말별 계정과 DB가 맞지 않음을 뜻하며 방송 대상에서 제외될 수 있으므로 `super_admin`에게 계정 조치 버튼을 제공한다.

### 6.2 배정·위치 수정

운영자는 label, 마을, 구역, 설치 주소와 좌표를 수정한다.

- 마을을 바꾸면 zone 목록을 새 마을 기준으로 다시 고른다.
- zone은 선택한 마을 소속만 허용한다.
- 주소 검색 결과가 도로명·지번·좌표를 함께 채운다.
- 지도에서 위치를 미세 조정할 수 있다.
- 단말 좌표를 비우면 zone, village 위치를 대신 사용한다.
- `village_admin`은 담당 마을 밖이나 미배정으로 옮길 수 없다.

마을 변경 저장 후 백엔드가 retained CONFIG와 ACL을 바꾸므로, 화면은 다음 STATUS의 CONFIG version과 마을 토큰 반영을 확인할 수 있어야 한다.

### 6.3 신규 등록

등록 모달은 다음 순서를 고정한다.

1. 모달을 열 때 서버 주소와 임의 MQTT password를 미리 발급한다.
2. QR/바코드를 스캔하거나 직접 입력한다.
3. MAC과 선택한 마을로 서버 등록을 확정한다.
4. 확정된 값을 USB Web Serial 또는 복사한 명령으로 단말에 주입한다.
5. 단말 재부팅 후 최대 30초 동안 서버 연결을 확인한다.
6. 필요하면 이 단말 한 대에만 짧은 파일 방송을 보내 실제 소리를 확인한다.

스캔 문자열:

```text
MAC|P4_MODEL|P4_VERSION|C6_MODEL|C6_VERSION
```

앞 5개 필드만 해석하고 뒤 필드는 무시한다. 직접 입력은 MAC만 필수다.

서버 주소 아래에 생산 라인 공유기 SSID·비밀번호 칸이 있다(문제점 35번). 둘 다 채우면 주입 프레임 맨 앞에 `@SSID`·`@PASSWORD`가 함께 나가고, 하나라도 비면 그 줄을 보내지 않는다. 값은 작업 PC의 localStorage에 지울 때까지 남으며 서버로 보내지 않는다.

스캔 입력칸은 브라우저 IME가 한글이어도 깨지지 않아야 한다. 물리 key code로 ASCII를 조립하는 것만으로는 부족하다 — keydown에서 `preventDefault`를 해도 IME는 자기 조합 결과를 입력칸에 따로 넣기 때문에 두 값이 섞인다. 입력칸을 편집 불가로 두고 값을 React 상태로만 채워야 IME가 조합해 넣을 대상이 사라진다. 붙여넣기는 `paste` 이벤트에서 직접 읽는다.

Web Serial:

- Chrome/Edge + HTTPS 환경
- 115200 bps
- 단말의 `@RESULT=OK`를 기다려 완료 표시
- 지원하지 않는 브라우저에서는 `@END`와 마지막 개행까지 포함한 명령을 복사하게 함

시험 방송은 반드시 `target_scope=device`, 해당 MAC 한 대, `store_flash=false`다. 파일함에 짧은 시험 MP3가 있어야 한다.

### 6.4 credential 재발급

기본 동작은 기존 password 조회다. 재발급은 생산 라인에서 단말에 새 값을 바로 다시 주입할 수 있을 때만 허용한다. 이미 현장에 설치된 단말은 서버 password만 바꾸면 연결이 끊기므로 경고를 명확히 표시한다.

[재발행 (라인 전용)]을 누르면 경고와 함께 **MAC 끝 4자리 입력칸**이 열리고, 맞게 넣어야 [재발행]이 눌린다(향후검토 2번, 2026-09-21). 삭제 확인과 같은 방식·같은 자릿수다 — 예전에는 확인창의 「확인」만 누르면 바뀌었다.

## 7. 방송하기 `/broadcast`

**2026-09-21 개편.** 쓰는 사람은 대부분 50대 이상 마을 이장님이다. 예전에는 방송이 세 화면(방송 제어·파일함 TTS·스케줄)에 흩어져 있어, 글로 방송 하나를 예약하려면 파일함에서 음성을 만들고 → 스케줄에서 파일·대상·시각을 다시 골라야 했다. 이제 한 화면에서 위에서 아래로 끝난다. 메뉴 맨 위 「방송하기」.

| 단계 | 화면 | 이장님이 누르는 것 |
|---|---|---|
| ① 어떻게 | 큰 버튼 셋: 마이크로 말하기 · 글로 써서 방송 · 저장된 소리 틀기 | 1번 |
| ② 어디에 | 담당 마을이 하나면 **미리 골라져 있다**(켜진 단말 수 표시). 여럿이면 기관 트리(§7.1)가 펼쳐져 있다 | 0번 |
| ③ 무엇을 | 글: 큰 입력칸 + 자주 쓰는 첫마디 버튼 + 「먼저 들어보기」. 소리: 목록에서 고르기(듣기 버튼) | 글 입력 |
| ④ 언제 | 한 줄에 넷: 지금 바로 · 날짜 정해 한 번 · 매일 · 매주(뒤 셋은 예약). 고르면 날짜(오늘·내일·모레)·요일과 오전·오후 시·분이 나온다 | 0~3번 |
| 맨 아래 | 「금산(켜진 단말 2대)에 적은 글을 지금 바로 방송합니다」 한 문장 + 큰 버튼 하나. 빠진 것이 있으면 문장 자리에 「③ 방송할 글을 적어 주세요」처럼 알린다 | 1번 |

마을 하나인 이장님이 글로 지금 방송하면 **글 입력 + 버튼 1번**으로 끝난다(① 은 지난번에 쓴 방법을 기억한다 — 처음이면 「글로 써서 방송」).

**배치.** 넓은 화면(901px 이상)은 두 칸이다 — 왼쪽 ①② , 오른쪽 ③④ 와 버튼. 화면 높이에 딱 맞춰 페이지는 스크롤하지 않고, 기관 트리·저장된 소리 목록만 제 칸 안에서 돈다. 글 입력칸은 남는 높이를 먹는다. 칸 높이가 모자라면(1366×768 노트북, 맨 위에 방송 중 띠가 떴을 때) 화면이 스스로 촘촘한 배치(`.bc--tight` — 여백·버튼만 한 단계 줄이고 예약 날짜·시각을 한 줄로)로 바꾼다. 폰은 한 칸으로 위아래로 흐르고 요약·버튼이 아래에 붙어 따라온다.

**시선 안내.** 아직 안 끝난 첫 단계의 테두리가 파랗게 은은히 숨쉰다. 끝낸 단계는 번호가 ✓ 로 바뀌고 빛은 다음 단계로, 다 되면 맨 아래 버튼으로 넘어간다. 방송을 거는 중·방송이 나가는 중에는 끈다(그때 볼 곳은 빨간 띠). 움직임 줄이기 설정에서는 파란 테두리만 남는다.

② 의 고르기를 접어 둔 동안(마을 하나인 이장님의 기본)은 그 자리에 **「방송이 나갈 단말」** 목록(이름·구역·켜짐/꺼짐)을 보여준다.

- 방송 중이면 맨 위에 빨간 띠(무엇을·어디에·경과 시간·응답 대수)와 큰 **「방송 끄기」**. 단말별 상태는 「단말별 상태 보기」를 눌러야 보인다.
- 글 방송은 방송할 때 음성을 만든다(서버 TTS → 파일함). 「먼저 들어보기」로 만든 음성은 문구가 같으면 다시 만들지 않는다. 들어보고 방송하지 않았거나 문구를 고쳐 다시 만든 음성은 지운다 — 방송 자료에 버린 음성이 쌓이지 않게. 방송·예약에 쓴 것은 남긴다.
- 예약은 스케줄 API 그대로다. **「한 번만」 예약이 새로 생겼다**(0020). 반복 예약은 단말 저장을 저절로 켠다. 구역·전체 대상은 스케줄이 지원하지 않아 예약 버튼이 막히고 이유를 알린다. 지난 시각은 화면이 먼저 막는다.
- 마이크 방송: 마이크를 못 잡으면(권한 거부·장치 없음·업링크 실패) 방금 만든 방송 세션을 곧바로 되돌린다 — 소리 없는 방송이 켜진 채 남지 않는다(2026-09-21 수정. 예전 화면은 세션이 남았다).
- 서버 쪽 장애(방송 서버·MQTT·5xx)는 「방송 서버에 연결하지 못했습니다…」로 보이고, 기술 문구는 그 아래 작은 글씨로만 남는다.
- 드물게 쓰는 설정(단말 저장, 녹음 저장, 읽는 언어)은 「자세히 설정」 안에 있다.
- 글자: 본문 17px, 단계 제목 22px, 큰 버튼 22px·높이 64px.
- 메뉴 이름도 이장님 말로 바꿨다: 방송하기 · 예약 방송(스케줄) · 마을 현황(대시보드) · 방송 자료(파일함) · 방송 기록(이력). 경로는 그대로다. 준비 중 메뉴(비용·OTA)는 최고 관리자에게만 보인다.
- 기존 「예약 방송」 목록·수정 창과 「방송 자료」 화면은 그대로 있다 — 목록 관리·파일 올리기·세부 반복(매월·매년)은 거기서 한다.

### 7.1 대상 선택

지원 범위:

**마을·구역·개별 단말은 같은 트리 하나로 고른다**(향후검토 7·8·9번, 2026-09-20). 종류만 바뀌고 조작은 같다.

```
기관 > (하위 기관) > 마을 > [구역 | 단말]
```

- 기관·마을: 마을이 잎. **기관을 체크하면 그 아래(깊이 무관) 마을 전체가 선택된다**
- 구역: 마을을 펼치면 구역이 잎. 마을을 체크하면 그 마을 구역 전체
- 개별 단말: 마을을 펼치면 단말이 잎. 마을을 체크하면 그 마을 온라인 단말 전체
- 전체: `super_admin`만 (트리 없음)

공통 규칙:

- **상위 기관은 직접 체크했을 때만 체크로 보인다.** 아래만 골랐을 때는 중간 표시(−)다. 예전에는 「아래가 전부 선택됨」을 체크로 표시해서, 선택 가능한 마을이 하나뿐인 기관은 그 마을만 골라도 상위까지 체크된 것처럼 보였다(향후검토 7번). 기관을 체크하면 아래는 상속으로 체크되고, 아래 하나를 해제하면 상위 체크가 중간 표시로 풀린다
- 기관 관리자는 자기 기관이 트리 맨 위라 도 계정이면 그 도를 바로 고른다. 이장은 기관 없이 담당 마을만 나온다
- **검색창**이 있다. 기관·마을·구역·단말 이름(MAC 포함)이 걸리는 가지만 남기고 펼치며, 없으면 「검색 결과가 없습니다」
- 구역·단말 모드에서는 마을을 접은 채로 연다. 구역 목록은 마을마다 따로 읽으므로 마을 50곳 이하면 미리 읽고, 더 많으면 펼치는 마을만 읽는다
- 선택 요약은 직접 체크한 기관·마을을 「경기도 전체」로 접어 보여준다
- 서버에는 항상 잎 목록으로 보낸다(`village` / `zone` / `device`). 기관 선택은 화면에서만 펼쳐지고 이력·겹침 검사·단말 프로토콜은 그대로다
- 온라인 단말이 없는 마을·구역·오프라인 단말은 고를 수 없고 상위 체크에도 들어가지 않는다

각 선택지는 등록 대수와 온라인 대수를 함께 보여준다. 오프라인 단말은 선택 목록에서 식별할 수 있어야 하고 실제 발행 대상은 서버가 온라인 기준으로 확정한다.

시작 버튼 근처에는 다음을 한 문장으로 요약한다.

```text
새뜰마을 외 1곳의 온라인 단말 18대에 실시간 방송합니다.
```

전체 방송은 영향이 크므로 파일 또는 마이크 종류와 온라인 대상 수를 다시 확인시킨다.

### 7.2 진행 중 방송 카드

모든 진행 방송을 상단에 표시한다.

- 방송 종류와 파일명
- 시작 시각·경과 시간
- `job_id` 보조 표시
- 서버 계산 phase
- 대상 수, 성공·실패·대기 수
- 단말별 result type, code, live, 품질 요약
- 마이크 업링크 연결 여부
- 준비 지연·무음·중지 대기 경고
- 중지 버튼

응답 progress bar의 분모는 `expected_count`다. 성공과 실패를 모두 “응답 도착”으로 세되 색상과 숫자는 분리한다.

LIVE 준비 지연 경고는 `live_ready_timeout_sec + 5초` 뒤 아직 READY가 없는 단말이 있을 때 표시한다. 경고는 자동 중지를 뜻하지 않으며 운영자가 계속·대기·중지를 판단한다.

### 7.3 실시간 방송

1. 대상과 “단말에 녹음 저장”을 선택한다.
2. 브라우저가 마이크 기능을 지원하는지와 secure context인지 확인한다.
3. 시작을 누르면 마이크 권한을 받는다.
4. 서버가 방송과 Icecast source를 만든다.
5. 브라우저가 WSS 인증 후 Ogg/Opus를 전송한다.
6. 화면에 마이크 meter, 연결 상태, 전송 KB를 표시한다.

진행 중 카드와 이력 목록의 대상은 서버가 내려주는 `target_label`(마을·구역·단말 이름, 전체는 「모든 마을」)을 쓴다. 내부 ID를 그대로 그리면 방송하는 사람이 어느 마을인지 알 수 없다.

마이크 연결에 실패하면 만든 방송을 즉시 중지해 무음 세션이 남지 않게 한다. 다른 창에서 방송이 끝나도 현재 창의 recorder와 WebSocket을 정리한다.

`record_flash`는 현재 기본 켬이다. 10분 넘길 방송은 사용자가 꺼야 하므로 체크박스에 이 제한을 바로 표시한다.

### 7.4 파일 방송

파일함의 MP3를 고르고 “단말에 저장” 여부를 선택한다. 현재 `autoplay=true`로 다운로드·검증 직후 자동 재생한다.

진행 표시는 두 국면을 구분한다.

- 전송 중: 단말별 FILE_RESULT 대기
- 재생 중: 검증 완료 후 파일 duration 동안 재생

FILE_RESULT는 재생 종료가 아니라 재생 시작 시점일 수 있으므로 즉시 방송 카드를 없애지 않는다.

### 7.5 충돌과 중지

409 `BROADCAST_OVERLAP`이면 겹치는 방송 ID와 단말 수를 보여주고 사용자가 기존 방송을 확인하도록 한다. 새 요청이 기존 방송을 자동 종료해서는 안 된다.

중지를 누르면 버튼을 “중지 중”으로 바꾸고 결과 수를 갱신한다. API 응답만으로 즉시 카드를 제거하지 않고, active polling에서 종료가 확인될 때 정리한다.

현재 백엔드의 가시성 제한으로 `village_admin`이 `device`·`zone` 대상으로 시작한 방송은 다음 active polling에서 숨겨지고 직접 중지할 수 없다. 권한 판정이 실제 대상 단말의 마을 기준으로 보완되기 전에는 village 단위 방송을 사용하거나 `super_admin`이 상태 확인·중지를 맡는다.

## 8. 파일함 `/files`

파일함은 고객 스택 전체 공용이다.

기능:

- MP3 업로드
- Google TTS 생성
- browser audio 미리듣기·정지
- source, 길이, 크기, 등록자, 등록일 표시
- 참조되지 않는 파일 삭제

업로드·TTS 생성은 방송을 자동 시작하지 않는다. 운영자는 반드시 미리듣기 후 방송 제어에서 파일을 선택한다.

업로드한 MP3는 서버가 방송 규격(16kHz mono, 설정 비트레이트)과 비교한다. 규격보다 음질이 낮으면 거절하고 사유를 보여준다. 규격보다 높으면 `AUDIO_NEEDS_TRANSCODE`를 받아 변환 여부를 확인 팝업으로 묻고, 확인하면 같은 파일을 `?transcode=true`로 다시 보낸다. 여러 파일을 한 번에 올릴 때 취소한 파일만 건너뛰고 나머지는 계속 진행한다.

TTS 모달:

- 문구 최대 1,000자
- 언어와 voice 선택
- 표시 파일명 선택 입력
- 합성 중 진행 상태
- 완료 후 미리듣기
- 동일 문구·언어·voice cache 재사용 여부 표시 가능

삭제 전 파일명을 포함해 확인한다. 이력이나 schedule이 참조하면 서버가 거부하고 사용자는 파일이 사용 중이라는 메시지를 본다.

## 9. 이력 `/events`

현재 화면은 `/api/dashboard/summary`의 `recent_events`를 사용해 최근 10건만 보여준다.

표시 필드:

- 종류
- 대상 scope와 IDs
- 시작 시각
- 종료 시각 또는 진행 중

아직 없는 기능:

- 기간·종류·마을·사용자·성공 여부 필터
- 페이지네이션
- 방송 한 건의 대상 snapshot과 단말별 성공·실패 상세
- CSV 내보내기
- village_admin의 전체·zone·device 방송 참여 이력을 정확히 보여주는 범위 계산

따라서 현재 메뉴 이름은 이력이지만 감사용 전체 기록 화면으로 간주하면 안 된다.

## 10. 설정 `/settings`

`super_admin` 전용이며 세 그룹을 섞지 않는다.

각 항목과 그룹의 설명은 이름 옆 「?」에 있다(향후검토 4번) — 마우스를 올리거나 누르면 열리고, 바깥을 누르거나 Esc로 닫힌다. 방송 제어의 실시간·파일 방송 설명도 같은 방식이다.

**저장 확인(향후검토 1번, 2026-09-21).** 단말 공통 CONFIG 값이 바뀌어 전 단말에 재발행되는 저장이면, 임의 네 자리 숫자를 띄우고 그대로 입력해야 저장한다. 틀리면 「확인 숫자가 틀려 저장하지 않았습니다」를 띄우고 반영하지 않은 채 빠져나온다. 응답 시간·오디오 품질처럼 서버 안에서만 쓰는 값만 바꿨으면 묻지 않는다.

### 단말 공통 CONFIG

- STATUS 주기
- LIVE_STATS 주기
- event QoS

저장하면 CONFIG 관련 값이 바뀐 경우 `config_version`이 증가하고 retained CONFIG를 전 단말에 재발행한다. 단말 관리 화면에서 다음 STATUS의 version을 확인한다.

### 서버 방송 응답 시간

- 파일 방송 시작·중지 결과 대기
- LIVE 준비 제한
- LIVE 종료 결과 대기

이 값들은 공통 CONFIG로 발행하지 않는다. LIVE 준비 제한만 다음 LIVE_START에 포함한다. 저장 완료 메시지는 실제로 CONFIG가 재발행됐는지를 구분한다.

### 오디오 품질

- 라이브 스트림 속도 (16 / 24kbps)
- MP3 파일 속도 (16 / 24kbps)

표본율 16kHz와 mono는 통신 사양 고정이라 화면에 두지 않는다. 이 값들도 공통 CONFIG로 발행하지 않는다. 라이브는 다음 방송부터, MP3는 이후에 올리거나 합성하는 파일부터 적용되며 이미 파일함에 있는 파일은 다시 인코딩하지 않는다.

## 10a·11. 지역 관리 `/regions`

기관 관리자 이상이 쓴다. 기관 관리와 마을·구역 관리를 탐색기 하나로 합쳤다(2026-09-12, [화면 설계 §10a·11](../spec/xWIFI_화면_설계_260815.md)). 구현은 `pages/RegionsPage.tsx`(트리·조작), `components/regions/VillagePanel.tsx`(마을 내용), `lib/orgtree.ts`(트리 세우기·부분 트리 합계 — 스케줄 위자드·계정 화면도 같이 씀).

왼쪽 트리 — 기관은 폴더, 마을은 파일. VS Code 파일 탐색기의 손놀림:

- 마디를 고르고 [새 기관]/[새 마을] → 그 폴더 바로 아래 입력칸, Enter 생성·Esc 취소·비우고 나가면 취소. 마을을 고른 채 누르면 그 마을의 폴더 안. 아무것도 안 골랐으면 최고 관리자는 뿌리, 기관 관리자는 자기 기관
- F2 이름 바꾸기, Delete 삭제(확인창), ↑↓←→ Enter 이동·접기·펼치기, 우클릭 메뉴, 검색(걸리는 마디만 남기고 전부 펼침), 모두 펼치기/접기
- 끌어다 놓기로 옮기기 → 확인 모달. 브라우저 HTML5 드래그가 아니라 포인터 이벤트로 직접 끈다(운영 PC 에서 OS 드래그가 끝맺지 못해 갇히던 문제). 순환·관할 밖·같은 자리는 놓을 자리로 표시되지 않는다. 기관 관리자의 자기 마디는 「내 기관」 태그가 붙고 옮기기·삭제 비활성. 뿌리로 올리기는 최고 관리자만
- 폴더 옆 「마을 n · 기관 n」, 마을 옆 「온라인/전체」. 삭제가 막히는 폴더(하위·마을·계정이 남음)는 버튼 비활성 + 이유 툴팁
- 「기관 없음」 묶음: `organization_id`가 null인 마을. 최고 관리자만 본다

오른쪽 패널:

- 기관: breadcrumb, 타일(하위 기관·마을·단말·온라인 — 아래 전부 합계), 하위 기관 목록, 마을 표
- 마을: 타일(단말·온라인·구역·`village_id`), 위치·주소 카드(Kakao 주소 검색 → 도로명·지번·법정동코드·좌표 자동, 되돌리기/저장), 구역 카드(추가·삭제), 단말 표(MAC·별칭·상태·구역·마지막 접속)와 단말 관리 링크

주소는 마을에만 있다 — 대시보드 지도가 찍는 것은 마을 좌표와 경계라서다. 기관 마디는 이름과 자리뿐이다. `village_code`는 읽기 전용 파생 식별자다. 마을 삭제는 단말 자체를 지우지 않고 미배정으로 되돌린다는 점을 확인창에 표시한다. 경계 도형은 이 화면에서 직접 그리지 않고 서버 import 작업으로 넣는다.

**옮기기가 건드리는 것과 안 건드리는 것.** 마을·기관을 끌어다 놓으면 바뀌는 것은 `villages.organization_id`(또는 `organizations.parent_id`) 하나다. MQTT 토픽·ACL·retained CONFIG·브로커 계정은 마을의 `village_code` 로만 정해지므로 **단말 쪽은 아무것도 바뀌지 않고 재발행도 없다**(마을 수정 API 는 `village_token` 이 바뀔 때만 단말을 건드린다). 권한 범위는 매 요청마다 트리에서 다시 계산하므로 놓는 즉시 옛 기관 계정에선 사라지고 새 기관 계정에 나타나며, 「관할 전체」 스케줄은 다음 실행 시각에 새 트리대로 펼쳐진다. 재로그인은 필요 없다.

운영 시 주의 — 버그가 아니라 규칙의 결과다([관리자 계층 설계](../spec/xWIFI_관리자_계층_설계_260908.md) §6.2·§8):

1. **방송 중인 마을을 옮기지 않는다.** 방송은 계속 나가지만(단말은 소속을 모른다) 옛 기관 관리자에게는 그 방송이 더 이상 보이지 않아 **중지할 수 없다.** 새 기관 관리자나 최고 관리자가 중지한다. 옮기기 전에 진행 중 방송이 있는지 확인한다.
2. **옛 기관 관리자가 그 마을에 걸어 둔 스케줄은 지워지지 않는다.** 계속 실행되며, 이제 새 기관 관리자에게 보이고 그쪽만 고치거나 지울 수 있다. 마을을 넘겨받은 쪽은 스케줄 화면에서 물려받은 규칙이 있는지 한 번 본다.
3. **자동방송이 가리키는 기관·마을·단말은 지워지지 않는다.** 삭제하면 「이 마을을 대상으로 하는 자동방송이 1건 있습니다 (매일 08:00 안내.mp3)」처럼 거절된다. 자동방송 화면에서 그 스케줄을 지우거나 대상을 바꾼 뒤 다시 지운다. 마을은 소속 단말을 가리키는 스케줄도 막는다. 마을을 다 옮겨 빈 기관이 돼도 그 기관에 건 「관할 전체」 스케줄은 기관 관리자에게 계속 보인다.

## 12. 계정 관리 `/users`

기관 관리자 이상이 쓴다. 나보다 아래의 계정만 보이고, 역할 드롭다운에는 기관 관리자·마을 관리자만 나온다.

- 계정 생성
- 비밀번호 변경
- 역할 변경
- 기관 관리자의 소속 기관 선택 (트리 순서·들여쓰기. 기관 관리자 본인의 마디는 목록에서 빠진다 — 같은 마디는 동료라 서버가 거절)
- village_admin 담당 마을 다중 지정
- 사용 기간 지정 (1~30일, 기본 15일, 또는 무기한)
- 계정 삭제

`super_admin`은 담당 마을·기관 선택을 갖지 않는다. 자기 계정과 마지막 `super_admin` 삭제는 막는다. 목록에는 username, 역할, 범위(기관 또는 담당 마을), 사용 기간, 생성일을 표시한다.

사용 기간이 끝나면 로그인이 막히고 정리 작업이 계정을 지운다. 목록에는 만료일과 남은 날짜를 함께 보이고 3일 이하로 남았거나 이미 지난 계정을 눈에 띄게 표시한다. 수정 화면에서 저장하면 기간은 요청 시각부터 다시 센다.

**비밀번호는 확인할 수 없다(향후검토 10번, 2026-09-21).** bcrypt 해시로만 저장하기 때문이다. 대신 계정 수정의 [임시 비밀번호 발급]이 새 비밀번호를 만들어 그 창에서 **한 번만** 보여준다(복사 버튼). 창을 닫으면 다시 볼 수 없다. 그 계정은 목록에 「임시 비밀번호」 태그가 붙고, 다음 로그인에서 「새 비밀번호 정하기」 화면만 쓸 수 있다(임시 비밀번호 + 새 비밀번호 두 번). 바꾸면 원래 화면으로 간다. 자기 계정에는 발급하지 않는다.

## 12a. 스케줄 `/schedules`

[스케줄 설계](../spec/xWIFI_스케줄_설계_260909.md) §8. 로그인 계정 전체가 쓴다.

- 오늘 방송 일정 / 관할 전체 스케줄 목록 / 7일 예정표. 오늘 일정과 예정표는 서버가 계산한 회차(`/api/schedules/occurrences`)를 KST 날짜로 묶어 그린다
- 목록의 각 행: 언제(「매주 월·수 오전 9:00」) · 어디에 · 무엇을 · 다음 실행 · 최근 결과(나감·건너뜀·실패, 사유는 툴팁) · 끄기/수정/삭제. 대상 전체가 내 범위가 아니면 「조회만」
- 추가·수정 위자드: 기관→마을 트리 → 단말 선택(기본 전체) → 매일·매주·매월·매년 + 상세(요일 격자 / 1~31 격자 / react-day-picker 달력) + 오전·오후·시·분 → 파일(파일함·MP3 올리기·TTS 로 만들기) → 확인 문장 → 스케줄 확정
- 라이브러리: react-day-picker v9, date-fns(`ko`). 그 밖의 달력·격자·트리는 직접 그린다

## 13. 준비 화면

`/costs`, `/ota`는 메뉴 위치와 권한만 잡혀 있고 기능은 없다. 준비 화면의 phase 표시는 내부 개발 순서일 뿐 운영자에게 완료 기능처럼 보이면 안 된다.

기능 구현 시 필요한 화면 최소 범위:

| 화면 | 최소 기능 |
|---|---|
| 스케줄 | 파일·대상·월·요일·시각, 활성화, 다음 실행, 최근 실행 결과, 충돌 skip |
| 비용 | 기간, 전체 실비용, 마을 추정 배분, 방송 시간·egress, 추정치 안내 |
| OTA | package·서명·목표 버전, 대상·온라인 대수, 진행률, 재부팅 후 버전 검증 |

## 14. 접근성·오류 처리 체크리스트

- [ ] 모든 입력에 시각 label과 `aria-label`을 제공한다.
- [ ] 상태 dot은 반드시 텍스트 label과 같이 쓴다.
- [ ] keyboard focus가 보이고 Tab 순서가 작업 순서를 따른다.
- [ ] modal은 focus trap, Escape 닫기, 닫은 뒤 원래 버튼 focus 복귀를 지원한다.
- [ ] 작은 회색 글씨에 핵심 경고를 넣지 않는다.
- [ ] 빨강·초록만으로 성공과 실패를 구분하지 않는다.
- [ ] 로딩 중 같은 명령 버튼의 중복 클릭을 막는다.
- [ ] 네트워크 재시도와 명령 재실행을 구분한다.
- [ ] API `error.code`로 분기하고 사람이 읽는 `message`를 표시한다.
- [ ] 전체·다중 마을 방송은 최종 대상 수를 시작 직전 다시 보여준다.
- [ ] destructive action의 영향 범위를 구체적으로 확인한다.
- [ ] 1280px 이하와 태블릿에서 표·지도·버튼이 겹치지 않는지 확인한다.
