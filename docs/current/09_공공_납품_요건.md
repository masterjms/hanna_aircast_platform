# xWIFI 공공 납품 요건 (공공 클라우드·온프레미스 전환)

기준일: 2026-10-12 (문제점 70번)

관련 문서: [인프라와 운영](06_인프라_운영.md) · [백업과 복구](08_백업_복구.md)

고객 요청 "공공 클라우드/온프레미스 전환에 대한 추가 상세 내용"에 대한 정리다. 이미 구현된 보안 기능, 클라우드 보안인증(CSAP) 기준에서 고를 수 있는 선택지, 기관 전산실로 옮길 때 이 시스템에서 바뀌는 점, 실제 납품 전에 남은 일을 차례로 적는다. 인증 제도와 각 사 서비스 범위는 바뀔 수 있으므로 "확인 필요"로 표시한 항목은 납품 시점에 공식 자료로 다시 확인한다.

## 1. 이미 구현된 보안·기록 기능

| 항목 | 현재 동작 |
|---|---|
| 접속 기록 | 로그인 성공·실패(비밀번호 틀림·없는 ID·기간 만료), 접속 IP·브라우저 정보, 로그아웃 시각을 `login_events`에 2년 보관. `GET /api/auth/logins`, 화면은 계정 관리 아래 |
| 비밀번호 규칙 | 3종류 조합 8자 이상 또는 2종류 조합 10자 이상 |
| 비밀번호 만료 | 90일. 지나면 로그인 때 변경을 강제 |
| 계정 잠금 | 연속 5회 실패 → 30분 잠금. 임시 비밀번호 발급 시 잠금 해제 |
| 자동 로그아웃 | 브라우저 30분 미사용 시 |
| 전송 암호화 | 관리자·단말 HTTP는 HTTPS(TLS 1.2/1.3). nginx에서 HSTS, `nosniff`, `X-Frame-Options`, `Referrer-Policy` 적용. 단말 MQTT는 MQTTS 8883 |
| 관리자 접속 IP 제한 | `infra/nginx/admin-allow.d/local.conf`. 관리자 화면(`/`), API(`/api`), 마이크 업링크(`/ingest`)에 적용. 단말 경로(`/dl/`, `/live/`, MQTT)와 `/health`는 제외 — 단말은 어디서나 붙어야 한다 |
| 중요 작업 재확인 | 계정 생성·삭제, 방송 파일 삭제는 마지막 단계에서 비밀번호를 다시 입력 |
| 방송 행위 기록 | 방송 기록에 요청한 계정을 함께 저장 |
| 보관 기간 | 방송 기록 150일, 스케줄 실행 기록 1년, 로그인 기록 2년. 백엔드가 매시간 지난 기록을 정리 |
| 단말 인증 | 단말별 MQTT 계정·ACL(자기 토픽과 자기 마을만) |
| DB 보호 (AWS) | RDS 비공개, EC2 보안 그룹에서만 접근, 저장 암호화, 접속 SSL 강제 |

보관하는 개인정보는 최소한이다: 계정 ID만 저장하고 이름·전화번호는 받지 않는다. 로그인 기록에 접속 IP와 브라우저 정보(User-Agent)가 남는다. 비밀번호는 어떤 형태로도 기록하지 않는다. 주민·주소 등 마을 주민 정보는 다루지 않는다(마을 주소·좌표는 시설 정보).

## 2. CSAP (클라우드 보안인증)

공공기관이 민간 클라우드를 쓰려면 원칙적으로 CSAP 인증을 받은 서비스를 써야 한다. 등급은 이용 기관이 시스템이 다루는 데이터 중요도로 정한다.

| 등급 | 대상(요약) | 분리 요구(요약) |
|---|---|---|
| 상 | 국가 안보·민감 정보 시스템 | 물리적 분리 |
| 중 | 비공개 업무 자료를 다루는 시스템 | 물리적 분리 |
| 하 | 개인정보를 포함하지 않는 공개 정보 위주 시스템 | 논리적 분리 허용 — 해외 사업자 리전도 인증받으면 사용 가능 |

- 하등급 시스템은 CSAP 하등급 인증을 받은 민간 클라우드를 쓸 수 있다.
- AWS 한국 리전은 CSAP 하등급을 받은 것으로 알려져 있다. **확인 필요:** 이 시스템이 쓰는 서비스(EC2, RDS, EBS 스냅샷, S3 등)가 인증 범위에 들어 있는지, 인증 유효기간.
- **확인 필요:** 이 시스템이 하등급에 해당하는지는 기관이 판단한다. 계정 ID와 접속 IP를 보관하므로 기관에 따라 개인정보 포함으로 볼 수 있다. 중·상으로 판정되면 국내 공공 리전 또는 온프레미스만 남는다.

기관 보안성 검토에서 보통 요구하는 자료와 현재 준비 상태:

| 요구 자료 | 준비 상태 |
|---|---|
| 자산 목록(서버·SW·버전) | Compose 서비스·이미지 목록은 [06 문서](06_인프라_운영.md) §2. 버전 고정 목록은 납품 때 작성 |
| 망 구성도·포트 | [06 문서](06_인프라_운영.md) §3, 이 문서 §4.2. 기관 망 기준 구성도는 새로 그려야 함 |
| 접근통제 | §1(IP 제한, 계정 잠금, 권한 4계층) |
| 암호화 | 전송 TLS, RDS 저장 암호화. 온프레미스 디스크 암호화는 기관 몫 |
| 로그 보관 | 로그인 2년, 방송 150일. 위·변조 방지는 §5 남은 일 |
| 취약점 점검 | 미수행 — §5 |
| 백업·복구 | [08 문서](08_백업_복구.md) |

| | AWS 유지 | 국내 공공 클라우드 (NHN Cloud, KT Cloud, Naver Cloud 공공존 등) | 기관 전산실 온프레미스 |
|---|---|---|---|
| 전제 | CSAP 하등급 범위 안에 쓰는 서비스가 포함 | 각 사 CSAP 인증 등급·공공 리전 서비스 목록 확인 | 기관 서버·망 제공 |
| 준비 기간 | 가장 짧음 — 현 구성 그대로, 인증 범위 확인과 서류 | 중간 — 계약(조달 등록 상품 여부 포함), 새 환경 구축, 데이터 이관 | 가장 김 — 장비 조달, 망 구성, 보안성 검토, 반입 절차 |
| 비용 구조 | 월 사용량 과금(EC2·RDS·전송량) | 월 사용량 또는 공공 단가 계약 | 초기 장비 구매 + 유지보수 계약, 사용량 과금 없음 |
| 운영 책임 | 우리(EC2·앱), AWS(RDS 백업·하드웨어) | 우리(VM·앱), 사업자(인프라). 관리형 DB 사용 여부에 따라 백업 책임이 바뀜 | 앱은 우리, 서버·망·백업 매체·물리 보안은 기관과 나눠야 함 — 계약에 명시 |
| 망 분리 대응 | 인터넷 서비스. 관리자 접속은 IP 제한으로 기관 망만 허용 | 공공존 안에서 같은 방식. 기관 전용 회선 연결 가능 여부는 사업자 확인 | 단말 수신용 DMZ와 관리자 업무망 사이 경계 설계 필요(§4.2) |
| 이 시스템에서 바뀌는 것 | 없음. 서류·확인만 | RDS → 사업자 관리형 Postgres(18 지원 확인) 또는 `local-db`. EBS DLM → 사업자 스냅샷. `backup-db.sh`의 S3 업로드와 `cost-report.sh`는 AWS 전용이라 쓰지 않거나 고쳐야 함 | §4 전부 |

공통: 앱은 Docker Compose 한 벌이라 Ubuntu + Docker가 되는 곳이면 코드 변경 없이 뜬다. 바뀌는 것은 DB 위치, 백업, 감시, 인증서, 외부 연동이다.

## 4. 온프레미스 전환 상세

### 4.1 구성

- RDS 대신 같은 `docker-compose.yml`의 `local-db` 프로파일로 Postgres 18 컨테이너를 쓴다: `docker compose --profile local-db up -d`
- `.env`에서 `DATABASE_URL`만 compose 서비스 이름 `postgres`로 바꾸고 `POSTGRES_USER`·`POSTGRES_DB`·`POSTGRES_PASSWORD`를 채운다. 코드는 그대로다. 자세한 순서는 [08 문서](08_백업_복구.md) §3.c.
- `PUBLIC_BASE_URL`, `ICECAST_PUBLIC_BASE_URL`은 기관 도메인(HTTPS, 포트 없이)으로 바꾼다. 단말은 http 스트림 주소를 거절한다.
- 단말에는 생산 등록 때 서버 도메인(또는 IP)이 주입된다. 서버 주소가 바뀌면 단말 재주입 또는 DNS 조정이 필요하다 — 도메인을 유지하는 편이 낫다.
- 권장 사양 시작점은 [06 문서](06_인프라_운영.md) §1(2 vCPU/4 GiB 수준, 약 300대). DB가 같은 장비로 들어오므로 메모리·디스크 여유를 더 잡는다.

### 4.2 포트와 외부 연결

들어오는 연결:

| 포트 | 출발 | 용도 |
|---|---|---|
| 443/TCP | 단말 회선, 관리자 PC | 관리자 화면·API, 단말 파일 다운로드(`/dl/`), 실시간 스트림(`/live/`) |
| 8883/TCP | 단말 회선 | MQTTS |
| 80/TCP | 인터넷 | Let's Encrypt 발급·갱신 때만. 다른 인증서를 쓰면 HTTPS 리다이렉트용으로만 |

단말은 보통 인터넷 회선(LTE·Wi-Fi)으로 붙으므로 서버는 인터넷에서 443·8883이 열려 있어야 한다. 폐쇄망 안에 두면 단말 회선도 그 망으로 들어와야 한다. 일반적인 배치는 서버를 DMZ에 두고 관리자 화면은 업무망에서만 허용(IP 제한 파일)하는 형태다.

나가는 연결과 막혔을 때의 영향:

| 대상 | 쓰는 곳 | 막히면 | 대안 |
|---|---|---|---|
| Google Cloud TTS | 파일함 TTS 합성 | TTS 생성 실패. 다른 방송 기능은 정상 | TTS를 끈다(`.env`의 `GOOGLE_APPLICATION_CREDENTIALS` 주석 처리) — MP3 업로드만 사용. 이미 만든 TTS 파일은 계속 방송 가능 |
| Kakao 주소 검색(서버) | 마을 주소 → 좌표·법정동코드 | 주소 검색 비활성(`KAKAO_REST_API_KEY` 비움) | 좌표·주소 직접 입력 |
| Kakao 지도 SDK(관리자 브라우저) | 대시보드 지도, 경계 | 지도 칸이 안내문으로 바뀜(`KAKAO_JS_KEY` 비움). 목록·상태는 정상 | 지도 없이 운영. 기관 GIS 연동은 별도 개발 |
| Slack webhook | `healthcheck.sh`, `backup-db.sh` 알림 | 알림이 안 간다. 백업 자체는 동작 | §4.6 |
| Docker Hub, pip, npm, Git | 이미지 빌드·업데이트 | `deploy.sh` 사용 불가 | §4.7 오프라인 반입 |
| Let's Encrypt | 인증서 발급·갱신 | 발급 불가 | §4.3 |

### 4.3 인증서

- nginx와 Mosquitto가 같은 `infra/certs/server.crt`(full chain), `server.key`를 쓴다.
- 단말은 TLS 서버 인증서를 검증한다. 따라서 **단말이 신뢰하는 루트 CA로 발급된 인증서**여야 한다.
  - 공인 인증서(상용 CA, DNS 검증 등): 단말 쪽 변경 없음. 폐쇄망이면 Let's Encrypt HTTP-01 자동 갱신이 안 되므로 1년 단위 수동 교체.
  - 기관 사설 CA: 단말 펌웨어의 신뢰 CA 목록에 기관 루트가 들어가야 한다 — **단말팀과 조율 필요**(펌웨어 변경). 관리자 PC에도 기관 루트 배포.
- 교체 방법: 파일 두 개를 바꾸고 `docker compose restart nginx mosquitto`. 권한은 [06 문서](06_인프라_운영.md) §8(개인키 `root:1883`, 640). Mosquitto 재시작은 단말 재접속을 일으키므로 방송 시간 밖에 한다.
- `healthcheck.sh`의 인증서 만료 경고(20일 전)는 폐쇄망에서도 동작한다(알림 경로만 §4.6).

### 4.4 시간 동기화

- 스케줄 실행기는 한국 시간(Asia/Seoul) 기준 1분 주기로 돈다. 서버 시계가 틀리면 예약 방송이 틀린 시각에 나간다. 호스트에 기관 NTP 서버를 지정한다(**수동**).
- 단말은 접속 전에 SNTP로 시간을 맞추고 그 뒤에 인증서를 검증한다. 폐쇄망에서 공용 NTP에 못 나가면 TLS 연결 자체가 실패한다. **확인 필요(단말팀):** 단말의 SNTP 서버 주소를 기관 NTP로 바꿀 수 있는지, 생산 등록 때 주입 가능한지.

### 4.5 백업

RDS 자동 백업이 없으므로 백업은 운영자 몫이 된다. `backup-db.sh` 일일 cron, `files` 볼륨 백업, 비밀 파일 보관, 분기 복구 훈련을 [08 문서](08_백업_복구.md)대로 한다. S3 업로드는 AWS 전용이라 폐쇄망에서는 기관 백업 서버·매체로 덤프 디렉터리(`~/db-backups`)를 복사하는 작업을 따로 건다(**수동**).

### 4.6 감시

- `healthcheck.sh`(디스크·메모리·컨테이너·`/health`·백업 최신성·인증서)는 그대로 돈다. Slack으로 못 나가면 `bash scripts/healthcheck.sh --dry >> ~/healthcheck.log`처럼 로그로 남기고 기관 운영자가 본다. webhook이 없으면 `--always` 모드는 결과를 화면에 찍고 실패 코드로 끝난다.
- 서버가 죽은 것은 서버 안 스크립트가 알 수 없다. 기관 관제 시스템(NMS 등)이 `https://<도메인>/health`를 1분 주기로 확인하도록 요청한다(`/health`는 IP 제한 대상이 아니다).
- `cost-report.sh`는 AWS 전용이라 쓰지 않는다.

### 4.7 업데이트 반입 (git pull 불가)

`deploy.sh`는 `git pull`과 `docker compose build`(인터넷에서 패키지 설치)를 하므로 폐쇄망에서는 그대로 못 쓴다. 외부에서 이미지를 만들어 반입한다. 아래는 개요이며 스크립트화는 §5 남은 일이다.

1. 외부 빌드 PC에서 납품 commit을 checkout하고 `docker compose build`.
2. 반입할 이미지 목록 확인: `docker compose --profile local-db config --images` (backend, frontend 빌드 이미지 + `postgres:18-alpine`, `eclipse-mosquitto:2`, `libretime/icecast`, `nginx:alpine`).
3. `docker save`로 tar 묶음을 만들고, 소스는 `git archive`(또는 `git bundle`)로 묶는다. 해시값을 함께 기록한다.
4. 기관 반입 절차(망연계·승인 매체)로 옮긴다.
5. 서버에서 해시 확인 → 소스 교체(`.env`, `infra/certs`, `infra/secrets`, `admin-allow.d/local.conf`는 유지) → `docker load`.
6. 진행 중 방송 없음 확인 → DB 백업(`backup-db.sh`) → `docker compose run --rm --no-deps backend python -m alembic upgrade head` → `docker compose up -d --no-build` → `docker compose restart nginx`(빼면 502) → `/health` 확인.
7. 되돌릴 때를 위해 이전 이미지 tar와 이전 소스 묶음을 한 벌 남겨 둔다.

`libretime/icecast:latest`처럼 `latest` 태그는 빌드 시점마다 내용이 바뀔 수 있으므로 납품 전에 버전을 고정한다.

## 5. 남은 일 (실제 납품 전)

| 항목 | 내용 | 비고 |
|---|---|---|
| 취약점 점검 | 웹 취약점 점검(모의해킹), 서버·DB·컨테이너 설정 점검, 조치 결과 보고서 | 기관 지정 기준·기관 확인 필요 |
| 개인정보 처리방침 | 기관 명의로 수정(수집 항목: 계정 ID·접속 IP·브라우저 정보, 보관 기간, 파기 방법) | 기관 담당자 협의 |
| 접속기록 위·변조 방지 | 현재 `login_events`는 운영 DB 안의 일반 테이블. 앱 계정의 수정·삭제 권한 분리(append-only), 별도 매체로 주기 백업, 월 1회 점검 기록 | 개발 + 운영 절차 |
| 관리자 2단계 인증 | OTP 등 추가 인증 검토(최소 최고 관리자) | 미구현 |
| 관리 행위 기록 | 로그인·방송 외에 계정 생성·삭제·권한 변경, 단말 등록·마을 이동 기록 범위 확인·보강 | 현행 범위 확인 필요 |
| 단말 MQTT 비밀번호 저장 | 생산 주입 때문에 DB에 평문 보관 중. 보안성 검토 지적 가능 — 컬럼 암호화 또는 주입 뒤 열람 차단 검토 | [02 문서](02_단말_연동_사양.md) §3.1 |
| TTS 자격증명 | 현재 개인 계정 토큰 방식. 기관 명의 계정·서비스 계정으로 전환하거나 TTS를 끈 채 납품 | |
| 암호모듈 | 검증필 암호모듈(KCMVP) 사용 요구 여부 | 기관 확인 필요 |
| OTA 코드 서명 | 펌웨어 패키지 서명 미구현 | 단말팀과 조율 |
| 망연계 | 업무망 ↔ DMZ 관리자 접속 경로, 업데이트 반입 경로(§4.7) 설계 | 기관 망 담당 |
| 단말 폐쇄망 대응 | 기관 CA 신뢰, SNTP 서버 지정(§4.3·§4.4) | 단말팀 확인 필요 |
| 오프라인 배포 스크립트 | §4.7을 스크립트로 만들기(`deploy.sh`의 방송 확인·마이그레이션 순서 재사용) | 개발 |
| 로그 관리 | 컨테이너 로그 회전 설정 없음, nginx 접근 로그 보관 기간 미정 | [06 문서](06_인프라_운영.md) §14.3 |
| 복구 목표 | 목표 복구 시간·허용 데이터 손실량을 계약 수치로 확정 | [08 문서](08_백업_복구.md) §2 |
| 납품 서류 | 자산 목록(버전 고정), 기관 망 기준 구성도, 운영자 매뉴얼 | |
