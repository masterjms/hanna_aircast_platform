# xWIFI 설치·인계 가이드 (기관 클라우드·온프레미스)

> 2026-10-15, 문제점 88번. 기관(지자체)이 계약한 클라우드(KT·NHN·네이버 공공존 등)나 기관 전산실 서버에
> 이 시스템을 설치해 넘길 때 쓴다. 납품 묶음 안에는 이 문서가 `설치_가이드.md` 로 들어간다.
> 지금의 AWS 운영(git pull + `deploy.sh`)은 [06 문서](06_인프라_운영.md) §12 그대로이고 이 문서와 별개다.

## 1. 납품 방식

기관이 국내 CSAP 인증 클라우드를 직접 계약하고, 우리는 그 위에 프로그램을 설치·인계한 뒤 SW 유지보수 계약만 맡는다.

| 방식 | 우리 부담 | 비고 |
|---|---|---|
| 우리가 운영하는 SaaS | CSAP 인증(우리 몫), 24시간 운영 | 부담 가장 큼 |
| 하드웨어 납품(온프레미스) | 서버 구매·설치·고장 대응 | 기관 전산실 필요 |
| **기관 클라우드에 설치형** | 설치·인계·유지보수 | 클라우드 계약·CSAP 는 기관 몫 |

기관 1곳 = 서버 1벌(도메인·인증서·DB·단말 계정이 기관마다 따로). 공공 납품 보안 요건과 클라우드 선택지는 [09 문서](09_공공_납품_요건.md).

## 2. AWS 종속 점검 결과

프로그램(백엔드·화면·브로커·DB·스트리밍)은 AWS 기능을 쓰지 않는다 — AWS SDK·S3·SQS·메타데이터 호출 0건, Docker Compose 한 벌. Ubuntu + Docker 가 되는 곳이면 코드 변경 없이 뜬다.

| 구분 | 지금 AWS 운영 | 다른 클라우드·온프레미스 |
|---|---|---|
| DB | RDS PostgreSQL 18 (표준 연결 문자열 하나) | 같은 compose 의 `local-db`(Postgres 컨테이너) 또는 사업자 관리형 Postgres 18 — `DATABASE_URL` 만 바꿈 |
| 서버 | EC2 + Elastic IP | VM + 고정 공인 IP |
| 방화벽 | Security Group | 사업자 방화벽·ACL (§3) |
| 디스크 백업 | EBS 스냅샷(DLM) | 사업자 스냅샷 또는 없음 — DB 는 `backup-db.sh` 일일 덤프 |
| DB 백업 사본 | `backup-db.sh` → S3 (선택) | `S3_BUCKET` 비우고 덤프 폴더를 기관 백업 서버로 복사 |
| 서버 접속 | SSM | SSH(관리자 IP 만) 또는 기관 원격 접속 규정 |
| 감시 | CloudWatch 상태 확인 | 사업자 감시 또는 기관 NMS 가 `https://<도메인>/health` 1분 주기 확인 |
| 비용 보고 | `cost-report.sh` (Cost Explorer) | **쓰지 않는다** — AWS 전용 |
| 서버 준비 | (수동) | `scripts/setup-server.sh` — 클라우드 무관 |

이번에 바꾼 것: `docker-compose.yml` 이미지 이름에 버전(`xwifi-backend:${APP_VERSION}`), Icecast 이미지 버전 고정(`2.4.4-debian`, 예전 `latest`), `setup-certs.sh` 공인 IP 조회를 여러 공개 서비스로, `cost-report.sh`·`backup-db.sh` 에 AWS 전용 표시.

## 3. 준비물 (기관에 요청)

| 항목 | 내용 |
|---|---|
| 서버 | Ubuntu 22.04/24.04 LTS, 2 vCPU · 4 GiB · SSD 50 GB 부터(약 300대). DB 가 같은 서버라 여유 있게. 1,000대 이상은 4 vCPU · 8 GiB |
| 고정 공인 IP + 도메인 | 단말은 생산 등록 때 서버 도메인을 받는다 — 도메인을 정한 뒤 단말 생산 |
| 들어오는 포트 | 8883(단말 MQTTS) · 443(관리 화면·파일 다운로드·실시간 스트림) · 80(인증서 발급·HTTPS 이동) — 인터넷 전체. 22 는 관리자 IP 만 |
| 인증서 | 단말이 신뢰하는 공인 CA 인증서. 80 이 열려 있으면 Let's Encrypt 자동 발급·갱신. 기관 사설 CA 는 단말 펌웨어 변경 필요(§7) |
| 시계 | NTP 동기화. 폐쇄망이면 기관 NTP 주소 |
| (선택) 외부 연동 | 카카오 지도·주소 검색 키, Google TTS 자격증명, Slack webhook — 없거나 막혀도 방송은 됨(09 문서 §4.2) |

## 4. 처음 설치

1. **서버 준비** — `sudo bash scripts/setup-server.sh` (Docker·시간대·swap·ufw). 끝나면 로그아웃 후 다시 접속.
2. **묶음 올리기·풀기** — 해시를 먼저 확인한다.
   ```bash
   sha256sum -c xwifi-<버전>.tar.gz.sha256
   sudo tar -xzf xwifi-<버전>.tar.gz -C /opt && sudo mv /opt/xwifi-<버전> /opt/xwifi && sudo chown -R $USER /opt/xwifi
   cd /opt/xwifi
   ```
3. **첫 실행 → `.env` 생성** — `bash scripts/install-offline.sh`. DB·JWT·MQTT·Icecast 비밀번호를 무작위로 채운 `.env` 를 만들고 멈춘다. `PUBLIC_BASE_URL`·`ICECAST_PUBLIC_BASE_URL` 을 기관 도메인(`https://…`, 포트 없이)으로 고친다. 지도·TTS·알림은 선택.
4. **인증서** — 인터넷에 열린 서버: `sudo bash scripts/setup-certs.sh <도메인> <이메일>`(Let's Encrypt, 90일 자동 갱신). 기관 인증서: `infra/certs/server.crt`(전체 체인)·`server.key` 를 넣고 키는 `sudo chown root:1883 server.key && sudo chmod 640 server.key`. 화면만 먼저 볼 때는 다음 단계에 `--self-signed`(단말은 거부).
5. **설치** — `bash scripts/install-offline.sh` 다시. 이미지 불러오기 → MQTT 서버 계정 → DB 기동 → 마이그레이션 → 최고 관리자 계정 → 기동 → `/health` 확인. **최고 관리자 비밀번호는 이때 한 번만 화면에 나온다** — 받아 적고 첫 로그인 뒤 바꾼다. 최고 관리자는 첫 로그인에서 **2단계 인증(휴대폰 OTP 앱) 등록**부터 한다 — 복구 코드 10개를 받아 보관한다. 최고 관리자를 두 명 이상 두면 한 사람이 휴대폰을 잃어도 다른 사람이 초기화할 수 있다(한 명뿐이면 서버에서 `docker compose exec backend python -m app.otp_reset <아이디>`).
6. **확인** — 브라우저로 `https://<도메인>` 로그인. 단말 한 대로 MQTTS 접속·CONFIG·파일 방송·실시간 방송을 끝까지 시험한다.
7. **운영 걸기** — cron: `backup-db.sh` 매일(덤프 폴더를 기관 백업 위치로 복사), `healthcheck.sh` 매일, `rotate-nginx-logs.sh` 매일(웹 접근 로그 1년 보관, [06 문서](06_인프라_운영.md) §13a). 관리 화면 접속 IP 제한은 `infra/nginx/admin-allow.d/local.conf`(견본 `local.conf.example`). 매달 계정 관리 아래 「기록 점검」에서 지난달 접속기록·관리 기록을 내려받고 「이번 달 점검 기록」을 누른다 — 파일 해시를 점검표에 적어 둔다.
8. **키 보관** — `.env`의 `DATA_ENCRYPTION_KEY`(단말 비밀번호 암호화 키)를 처음에 따로 정하고 `.env`와 함께 안전한 곳에 보관한다. 비워 두면 `JWT_SECRET`에서 파생되므로 그 값을 바꾸면 안 된다(06 문서 §8).

## 5. 업데이트

```bash
sha256sum -c xwifi-<새버전>.tar.gz.sha256
tar -xzf xwifi-<새버전>.tar.gz --strip-components=1 -C /opt/xwifi
cd /opt/xwifi && bash scripts/install-offline.sh
```

- 같은 폴더에 덮어 푼다. `.env`·`infra/certs`·`infra/secrets`·`admin-allow.d/local.conf`·MQTT `passwd` 는 묶음에 없어서 그대로 남는다.
- 스크립트가 진행 중인 방송을 확인하고(있으면 멈춤, `--force` 로 진행), DB 를 백업한 뒤, **컨테이너 교체 전에** 마이그레이션한다. 마이그레이션이 실패하면 기존 서비스가 그대로 돈다.
- 인터넷이 없어도 된다(이미지는 묶음 안). 원격 접속이 안 되는 기관은 묶음 파일을 전달하고 기관 담당자가 위 세 줄을 실행한다.

**되돌리기:** 이전 묶음을 같은 방식으로 다시 풀고 스크립트 실행. 새 버전이 DB 구조를 바꿨다면 업데이트 직전 백업(`~/db-backups`)을 `restore-db.sh` 로 되돌린다 — [08 문서](08_백업_복구.md).

## 6. 묶음 만들기 (개발 쪽)

인터넷이 되는 빌드 PC(Docker, Git Bash 또는 Linux)에서:

```bash
git checkout <납품 커밋 또는 태그>
bash scripts/package-release.sh 1.0.0
```

`dist/xwifi-1.0.0.tar.gz`(+ `.sha256`) 한 파일이 나온다 — 이미지 6개(backend·frontend 빌드본, postgres·mosquitto·icecast·nginx), compose, `infra/`, `scripts/*.sh`, `.env` 견본, 이 가이드. `.env`·인증서·비밀번호·TTS 키는 들어가지 않는다. 기관마다 어느 버전을 설치했는지 납품 기록에 남긴다(버전 = 묶음 이름).

## 7. 단말과 맞출 것

- **서버 주소:** 단말은 생산 등록 때 서버 도메인을 받는다. 기관마다 도메인이 다르므로 **현장에서 접속 주소를 바꿀 수 있어야** 한다 — 단말팀 확인 필요.
- **인증서:** 공인 CA 면 단말 변경 없음. 기관 사설 CA 면 단말 신뢰 CA 목록에 기관 루트가 들어가야 한다(펌웨어).
- **단말 계정:** 단말별 MQTT 계정은 그 기관 서버가 발급한다(단말 등록 → DB → passwd). 다른 서버에서 쓰던 단말을 옮기면 새 서버에 다시 등록한다.
- **시계:** 단말은 SNTP 로 시간을 맞춘 뒤 인증서를 검증한다. 폐쇄망이면 SNTP 주소를 기관 NTP 로 — 단말팀 확인 필요(09 문서 §4.4).

## 8. 유지보수 계약에서 챙길 것

- 원격 접속은 기관 규정(접속 승인·VPN·접속 기록)을 따른다. 안 되면 묶음 전달 + 기관 담당자 실행.
- 백업 사본 보관 위치와 복구 훈련(분기 1회)의 책임을 계약에 적는다.
- 인증서 갱신: Let's Encrypt 는 자동(80 포트 열림 전제). 기관 인증서는 만료 전에 기관이 새 파일을 준다 — `healthcheck.sh` 가 20일 전 경고.
- 납품 전 보안 보완(취약점 점검·관리자 2단계 인증 등)은 09 문서 §5.
